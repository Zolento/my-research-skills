# 示例：串联调用 A → B → C

演示完整链路：从领域关键词出发，到 idea 清单（**含 idea 级审核**），再到提案，
最后到七子代理方案审查。

> 记住分工：**A 管"值得做吗"，C 管"做对了吗"。**

---

## 1. 调用 Mode A

```
调用 research-idea-pipeline，mode=A
输入：领域关键词="扩散模型 + 组合优化"，参考文献=[...]
```

**执行要点：**

1. **A1** 内联执行 Mode D：本地 + arxiv 并集检索（本地命中不终止），产出技术路线
   归纳表与创新性边界。
2. **A2** 逐路线做深度局限性分析 —— 每条"没做到"必须指向**具体未建立的结构性质**。
3. **A3** **同一轮并发**派遣 6 个头脑风暴子代理（R-CVPR / R-ICML / R-NeurIPS /
   A-Author / A-Experimenter / S-Devil），每人 ≥3 个 idea，汇总去重后 ≥10 个。
4. **A4** 标注每个 idea 的推导策略。
5. **A5 idea 级审核（不可跳过）** —— 对每个候选派 三审稿人（创新性）+ S-Lit/S-Nov
   （重叠度）+ S-Feas（概念可行性）+ S-Theory（前提）+ S-Devil（致命反驳）。
   **不派 S-Repro。** 进入 shortlist 的 idea 必须完成 **L3 穷尽检索**。
6. **A6** 输出：≥10 个 idea（每个带审核结论）+ shortlist + 淘汰清单。

**产物片段（idea 清单）：**

| 编号 | 推导策略 | 核心思路 | 与现有工作差异 | 贡献类型 | 来源 | 创新性 | 可行性 | 重叠度 | 优先级 |
|---|---|---|---|---|---|---|---|---|---|
| I1 | 假设挑战 | 用扩散过程的可逆性约束组合优化搜索空间 | 现有方法把扩散当采样器，未利用可逆性作可行性约束 | Concept & Feasibility | R-ICML | 4 | 3 | 足够 | 高 |
| I7 | 组合创新 | 把 A 的注意力机制搬到 B 的图搜索 | 仅换模块，无新结构性质 | Use-Inspired | A-Author | 2 | 4 | 不足 | 建议放弃 |

**淘汰清单：** I7 —— 重叠不足，实质已被 [作者, 会议/年份] 覆盖 → 记入 INDEX 的
**已证伪**。

**落盘：** `docs/routeA/A001-idea-discovery.md` + 更新 `routeA/INDEX.md`

→ `next_mode_suggestion: "B"`

---

## 2. 调用 Mode B

```
调用 research-idea-pipeline，mode=B
输入：idea="I1: 用扩散模型的可逆性约束组合优化搜索空间"
```

**执行要点：**

1. **B1** 三审稿人视角独立评估创新性并**引用具体标准条目**；S-Lit 核实最接近
   先前工作并给出重叠度判定（L3 穷尽检索）。
2. **B2** S-Feas 给可行性评分 + 瓶颈；S-Theory 检查理论基础与隐含假设。
3. **B3** 六节提案展开，其中 §4 动机必须回答"为什么之前没人这么做"。
4. **B4** 十三节实验流程，含贡献—实验映射表与证伪条件。

**产物：** 论文提案（1500—2000 字）+ 实验流程计划书 + 创新性判定 + 可行性评分
+ 风险清单。

**落盘：** `docs/routeA/A002-proposal.md` + `A003-experiment-plan.md` + 更新 INDEX

→ `next_mode_suggestion: "C"`

---

## 3. 调用 Mode C（首次复核）

```
调用 research-idea-pipeline，mode=C
输入：proposal=上一步输出
```

**执行要点：**

1. **C1** 判定为**首次复核**（无上一次审阅内容）。
2. **C2** 派遣七子代理：每人 **1—5 分** + ≥200 字意见（S-Repro ≥150 字）。
   焦点是**方法正确性与工程可行性**，不是重复 A 的概念评估。
3. **C2.2 防复现检查（重点）** —— S-Lit 主责，逐项回答 §C2.2 的六项：

   | 检查项 | 判定 |
   |---|---|
   | 是否存在可一对一对应的已有方案？ | 部分 |
   | 增量是设计改变还是实现优化？ | 设计改变 |
   | 是否触及新的结构性质？ | 是（可逆性作为硬约束） |
   | 原样重跑已有方案，本方案声称是否仍成立？ | 否 |
   | 是否只是换数据集/backbone？ | 否 |

   → **复现风险等级：低**

4. **C3** 交叉质询：每人至少一条质疑；评分差 ≥2 分记录分歧；汇总取**中位数**。
5. **C4** 结论卡片（含**复现风险等级**与**方法正确性判定**）。

**产物：** 七子代理评审意见 + 交叉质询记录 + 审查结论卡片 + 横向对比表。

**落盘：** `docs/routeA/A002-review.md` + 更新 INDEX（结论翻译成进度条目）

→ 若仍有未解决项，`next_mode_suggestion: "C"`（进入接续复核）
