# Scientific Communication Policy（科研汇报优先）

> **定位：** 本文件是**面向用户汇报**的默认政策，不是新的 R 阶段，不是 Research State
> 对象，也不是 R12 叙事协议。它只决定「同一批已验证事实，先说什么、说多深、隐去什么」。
>
> **权威顺序：** canonical Research State、冻结预注册、原始实验产物与既有证据门禁
> **高于**本文件。本文件不得改变任何科学结论、claim 状态、实验授权或预算。
>
> 相关文件：[operational-autonomy-policy.md](operational-autonomy-policy.md)、
> [evidence-policy.md](evidence-policy.md)、[writing-policy.md](writing-policy.md)、
> [invocation-prompts.md](invocation-prompts.md)、[scheduler-policy.md](scheduler-policy.md)。

## 0. 默认目标

默认汇报的目标是让研究者**更快做出下一个科学决定**，不是证明 Agent 做了多少操作。

因此默认顺序固定为：

```text
Problem → Insight → Method → Evidence → Decision
```

**先给结论。** 第一段回答「现在科学上知道了什么、因此要做什么」。实验编号、配置名、
PID、GPU、路径、状态版本与同步动作放后，且只在影响判断时出现。

## 1. 五段结构

| 段 | 必须回答 | 典型内容 |
|---|---|---|
| **Problem** | 当前科学问题是什么？它对项目主锚点有什么影响？ | 待区分的机制、未满足的成功判据、当前瓶颈 |
| **Insight** | 新证据改变了哪一条机制认识？还有哪些竞争解释？ | 机制假设、替代解释、被排除与被保留的部分 |
| **Method** | 方法原理是什么？数学对象或优化机制改了什么？ | 目标函数、近似、假设、与最近方法的实质区别 |
| **Evidence** | 最重要的定量结果、对照、不确定性与证据边界是什么？ | 点估计、区间、对照臂、适用范围、失败条件 |
| **Decision** | 下一步最有信息价值的实验是什么？判别标准是什么？ | 最小判别实验、通过/失败判据、停止或转向条件 |

### 1.1 按研究阶段调整篇幅

五段是**顺序**，不是等长模板。按本轮任务动态分配：

| 本轮任务 | 重点段 | 应压缩的内容 |
|---|---|---|
| 新方法提出或方法修改 | **Method** | 实验编号、运行配置、状态同步 |
| 新结果落盘 | **Evidence → Decision** | 方法背景若已解释过，只写本轮变化 |
| 负结果或 mixed outcome | **Insight → Evidence** | 运行过程；必须写清排除了什么、什么仍然成立 |
| 方案被门禁阻塞 | **Decision** | 失败路径细节；只保留阻塞原因与解除条件 |
| 探索 / 候选生成 | **Problem → Insight** | 评分、venue、实现细节 |
| 用户显式要求审计 | 全部展开 | 不压缩；见 §5 |

**不得为了凑满五段而生成空泛内容。** 没有新 Insight 就写 `none`，没有新证据就写
`none`，并说明当前依据仍是哪条既有证据。**「文档数量、状态版本、执行次数」不是进展。**

### 1.2 先结论，后依据

返回对话时第一段必须是科学结论或研究决定。依据、推导、实验编号与运行信息放后面。
不得用「我先同步一下状态」「我先更新记录」开头。

## 2. Method-depth 检查

当报告**提出或修改一种研究方法**时，原则上必须回答下面六问：

1. **为什么需要该方法？** 现有方法在什么条件下失效，或哪个科学问题无法被区分？
2. **它改变了什么数学对象或优化机制？** 目标、变量、约束、近似、梯度或采样过程
   具体改了什么？
3. **相比最接近的已有方法，真正区别是什么？** 不得只写「结合了 A 和 B」。
4. **哪些假设使其可能有效？** 逐条写出假设，并说明假设被违反时会怎样。
5. **最可能的失败机制是什么？** 不是「可能不 work」，而是可指认的机制。
6. **哪个实验可以区分该机制与竞争解释？** 必须给出可判定的判据。

**无法回答时明确标注未知**，写成 `unknown` 或「尚未建立」，并说明缺少什么证据。
**不得生成空泛解释。** 例如「通过引入更强的表征提升性能」不是机制解释。

**方法来源必须可核验：** `原创` / `部分原创` / `迁移`。不得把迁移包装成原创。
**工程 smoke 只证明可执行性，不是科学有效性证据。**

## 3. 证据纪律

1. **不得把相关性写成因果性。** 除非有干预或识别设计，只能写「与……同向/相关」。
2. **不得把 engineering smoke 当作科学有效性证据。** 跑通、无 NaN、能保存 checkpoint
   都不是方法有效的证据。
3. **不得编造数学目标、机制或统计结论。** 公式、定理、区间与检验必须来自实际推导或
   实际计算。
4. **必须写统计不确定性与证据边界。** 点估计必须带区间或明确的方差信息；没有区间时
   标注 `unknown`。
5. **必须保留负证据。** 负结果、mixed outcome、被排除的假设与仍然成立的竞争解释
   都不得因为追求简洁而删除。
6. **不得把 UNKNOWN / INVALID 读成支持或否证。** 无效执行不进入科学负知识。
7. **不得把过期 telemetry 当作当前实验事实。** 进程终止、旧监控记录与旧 scheduler
   都不是科学 outcome；见 [operational-autonomy-policy.md](operational-autonomy-policy.md)。
8. **重要证据要可追溯，但引用要简洁。** 用 `X88`、`E110`、`F42`、`U66` 或
   `file:line` / JSON pointer 即可；默认不贴长绝对路径。

## 4. 默认隐藏的操作细节

以下信息**默认不进入用户汇报主文**：

- PID、进程号、GPU UUID、节点名、队列 ID；
- 文件大小、checkpoint 字节数、缓存命中数；
- 内部 `state_version`、索引版本、投影刷新次数；
- 长绝对路径、远端 root、临时目录；
- 与科学判断无关的状态同步、日志归档、索引维护动作；
- 重复的门禁自检输出与命令回显。

**例外：** 当且仅当这些信息**改变研究判断**时才出现，例如：

- 运行状态影响成本、进度或有效性（长 pilot、预算将尽、实验被终止）；
- 证据来源必须定位到具体运行或文件才能复核；
- 门禁阻塞由路径、权限、文件损坏或版本冲突造成；
- 用户显式要求审计、调试或完整记录。

即使出现，也写成**一行影响说明**，不展开操作流水账。例如：

> 运行状态：X90 pilot 正常（约 416/512），预计仍需数小时；不影响当前方法判断。

## 5. 审计 / 调试 / 完整记录模式

用户显式要求「详细审计」「调试」「完整记录」「把所有证据和路径给我」时，切换到详细模式：

- 完整列出证据 ID、来源文件、路径、运行信息、PID/GPU（如存在）；
- 列出被隐藏的维护动作、失败原因与重试记录；
- 保留逐条门禁结果与未决项；
- 仍然不得编造、不得改变科学结论、不得把 UNKNOWN 写成 PASS。

**详细模式是同一事实的展开，不是另一套结论。** 默认模式与详细模式对科学结论必须一致。

## 6. 与 R12 的边界

**R12 是论文叙事机制，不是日常科研汇报。** 本政策不调用 R12 的六槽位、preset、
盲恢复或叙事门禁。

- 日常汇报不要求「故事线」「卖点」「reviewer 可读性」；
- 不得为了汇报顺畅而改变 claim 强弱、证据边界或失败记录；
- 需要写论文叙事时，仍走 R12 的 claim-first 与证据约束流程。

## 7. 汇报前自检

- [ ] 第一段是科学结论或研究决定，不是操作日志。
- [ ] 五段顺序存在，但篇幅按本轮任务调整。
- [ ] 提出/修改方法时，六问已有实质回答或明确标注 `unknown`。
- [ ] 相关性未被写成因果性；smoke 未被写成有效性。
- [ ] 负结果、mixed outcome 与竞争解释仍然可见。
- [ ] 定量结果带不确定性或明确标注缺失。
- [ ] 默认隐藏项未被无理由展示；展示项均影响判断。
- [ ] 证据引用简洁可追溯；没有编造公式、机制或统计。
- [ ] 用户要求详细审计时，已切换到完整模式。
- [ ] 没有把日常汇报改造成 R12 叙事。
