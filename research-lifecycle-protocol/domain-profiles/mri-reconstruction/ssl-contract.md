# SSL Contract（自监督信息边界）

> 加载时机：任何涉及训练输入、损失构成、模型选择或"训练是否成功"的判断之前。

## 1. 信息拆分

自监督重建把测量拆成互不重叠的部分（以 SSDU 类为代表；具体拆分结构由项目协议决定）：

```text
Ω   = Θ ∪ Λ        # Θ：训练输入可见测量；Λ：损失留出测量
Ω_val              # 独立验证测量集合或验证拆分（模型选择）
```

配置里 `ssl.split` 必须逐项声明：`input`（Θ）、`loss`（Λ）、`held_out_validation`（Ω_val）。
ACS 的处理方式（是否进输入、是否冻结、是否单独留出）必须显式声明（`ssl.acs.usage`）。

## 2. 可机械检查的信息边界

| 检查 | 规则 |
|---|---|
| 训练输入 | 只允许 Θ（加按冻结协议声明的 ACS）；出现 Λ 或 Ω_val 的测量进入输入 → 违规 |
| 损失 | 只允许 Λ 上的一致性损失；损失引用 Ω_val → **hidden leakage**，违规 |
| 模型选择 | 只允许 Ω_val 或按冻结协议的外部验证；`gt.available: false` 时选择引用 GT → 违规 |
| GT 参与 | `gt.usage: none` 时，训练 / 选择 / 早停任何环节引用 GT → 违规 |
| 泄漏路径 | 数据增强、mask 生成、归一化统计不得使用留出信息；发现即违规 |

违规处理：受影响的实验结果**不得**支撑任何 claim；按 R10 修复后重新预注册。

## 3. 自监督损失 ≠ 重建质量

```text
ΔL_SSL < 0  ⇏  ΔE_image < 0
Lower SSDU loss ⇏ Better reconstruction
```

- SSL 目标改善而图像指标未改善：必须记为 **objective mismatch**（R9.O 的分析对象），
  值得研究"目标函数与重建误差的偏差来自哪里"，**不是**"训练成功"，也**不是**
  自动回退到"噪声太大"。
- SSL 目标未改善而图像指标改善：同样记录（说明目标与真实目标脱钩的方向）。
- 两种情况都必须带冻结判据与具体指标数值；不得用"总体上变好"一笔带过。

## 4. GT-free 边界

- 严格 GT-free 项目：训练与模型选择全程不接触 GT。独立离线 GT 评价可以存在，
  但只能作为**外部审计**，结果不得反向参与训练、早停、checkpoint 选择或超参搜索。
- GT 辅助开发分析与真正 GT-free 模型选择**必须分开记录**：混合两者的结论一律标注
  "GT-assisted"，不得写成 GT-free 结论。
- 报告里"GT-free"三个字只能用于实际满足上表的流程。

## 5. 与 RLP 核心的衔接

- 信息边界违规属于 **VALIDITY_BLOCKER**：优先级高于一切方法探索（TAG 不得压制它）。
- objective mismatch 属于 **NOVEL_DECISION_RELEVANT_DIAGNOSIS**（有新证据、能改变
  方法选择），MMS 方向 A（自监督信息利用机制）是它的合法去向。
- SSL 拆分结构的修改是实验条件变更，需要新的冻结预注册；不得在结果产生后改拆分。

## 6. 常见错误（本 Profile 明确禁止）

- 用 Ω_val 早停后宣称 "GT-free 模型选择"。
- 把 Λ 中的一部分悄悄并入输入以稳定训练，却不更新冻结协议。
- 用 SSL loss 曲线作为"方法有效"的唯一证据写进 claim。
- 把"SSL loss 没降"当成"机制被否证"（损失与图像指标本就不是同一对象）。
