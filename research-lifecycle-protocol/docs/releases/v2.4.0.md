# v2.4.0 — 执行边界与目录合规分离

日期 2026-11-20。目标 tag `research-lifecycle-protocol/v2.4.0`（合并进 `main` 后打）。

## 为什么改

v2.3.1 的组织规范有一条结构缺陷：`AGENTS.md` 既是项目事实的载体，又是
`references/project-layout.md` 规则的副本，而优先级规则让副本胜出。于是 DI-1—DI-8 在每个
有 `AGENTS.md` 的项目里退化为建议，且没有任何脚本读项目文件树。

六个真实项目的实测漂移：

| 项目 | 现象 |
|---|---|
| MoSA | 37 个顶层目录；`AGENTS.md` 43 KB；`experiments/A/TPOT-*` 非 XID 目录 |
| 3D_ZS_SSL | 控制目录 31 份 `research-state.*.json`；`log/` 与 `logs/` 并存；`.rlp-archive` |
| UC-Mamba-MRI | `experiments/<name>/` 无路线层；`results/{figures,logs,metrics}` 平行目录 |
| PCD-SSDU | `results/baselines/`、`logs/{jssl,ops}/` 无路线层 |
| SSDU-theorem | 根级 `figures/`、`research/`、`texput.log` |
| FusionSENSE-Lite | 根级 `FUSIONSENSE_INDEPENDENT_AUDIT.md`、`results/{audit,web-run}/` |

同一条「纯伴随换算与密度补偿禁令」在 Skill 里不存在，却在上述项目中出现 6 次、3 种条目数
（3 / 6 / 8 条）。副本已经漂移，且没有机制发现。

## 改了什么

### 四层分工

| 层 | 载体 | 只管 |
|---|---|---|
| 执行边界 | 项目根 `AGENTS.md` | 入口、写入范围、文件归属、项目事实 |
| 科研生命周期 | 本 Skill | R0—R14、state、证据资格、审查与决策门禁 |
| 具体实验 | 项目契约 + 预注册 + 冻结配置 | 数据划分、判据、预算、指标实现 |
| 目录合规 | `scripts/layout_guard.py` | DI-1—DI-8 的机械判定 |

### 优先级：布局可以让，门禁不能让

用户当前指令 ＞ 已冻结实验协议 ＞ `AGENTS.md` 的布局与写入范围 ＞ RLP 默认布局。
**RLP 的状态转换、证据资格与强制门禁不受该顺序影响**；`AGENTS.md` 不能豁免它们。
`AGENTS.md` 与本文件重复记述同一条规则时，按内容错误处理：删副本、留指针。

### `layout_guard.py`

```bash
python3 scripts/layout_guard.py preflight --kind route-doc --path routes/A/docs/A003-proposal.md
python3 scripts/layout_guard.py check      # Git 新增 / 暂存新增
python3 scripts/layout_guard.py audit      # 全树审计：block / warn 分级
python3 scripts/layout_guard.py selftest
```

退出码 0 / 3（路径违规）/ 4（环境：根不存在、双存储根、策略文件非法、宽例外模式）。
判定十项：13 类路径 kind、route 登记、XID 登记（预注册 / manifest / state 三处）、
`routes/<R>/docs/` 扁平、根 `docs/` 不放路线文档、`results|logs|checkpoints` 只收裸 XID、
`experiments/` 只收三个登记文件、软链接穿越、受保护入口、`AGENTS.md` 体量。

**例外只认** `.research-lifecycle-protocol/project/layout-policy.json`：模式必须窄
（`paper/*.tex` 可以；`**/*.md`、`*.md`、绝对路径、`../`、`dataset/*` 一律拒绝，退出码 4），
必须写授权人与理由。宽模式等于关掉保护。

### 模板

- `templates/AGENTS.project.md`（6.6 KB）：四层分工 / 启动与权威 / 路径归属 / 执行闭环 /
  权限与协作 / MRI 受管块 + 项目配置。**不命名为 `AGENTS.md`** —— 该名字会被 agent 运行时
  当作指令自动加载，等于给每个会话注入一份未填的项目契约（本轮实现时实际触发过一次）。
- `templates/layout-policy.template.json`：例外登记骨架。

## MRI Research Contract v1.0 接入

`training-policy.md` 的受管段重写为 Contract v1.0 简版，注入项目根 `AGENTS.md` 的仍是
`BEGIN/END RLP MRI TRAINING` 一段，不产生第二份 MRI 文字。全文副本在
`docs/contracts/mri-research-contract-v1.0.md`。

| 规则 | 机器判定 |
|---|---|
| 划分与 3D 病例隔离 | 审查 + 预注册绑定；发现违规 HOLD，不自改 |
| 两种合法选模 | `selection` ∈ `full_val_gt` / `gt_free_frozen`，前者要 GT 可用，后者要六个冻结字段与真实预注册文件 |
| 主指标 | `best_val_metric` ∈ `PSNR` / `complex_NMSE`；`NMSE` 不再含糊放行 |
| 训练前报告 | 九个必填字段 + `report_ref`，缺项 `MRI_TRAINING_REPORT` |
| **CSM 来源（MRI-10）** | `csm.mode` ∈ `dataset_stored` / `joint_estimation` / `not_applicable`；默认前者的 `source` 与 `sample_identity` 必填；后者要 `protocol_ref`（文件须存在）与 `eval_reference` |
| 领域 profile 一致 | `acquisition.coil_sensitivity.mode` 声明后必须与训练配置相同（DP3 + 绑定核对） |

两条设计判断：

1. **GT-free 不再被强制改成 `full_val_gt`。** v2.3.1 把 `selection` 写死成一种值，
   用户批准的 GT-free 方案文档加了也跑不起来。现在两种模式是平等的，缺方案才拒绝。
2. **联合估计灵敏度的例外不延长到评估参考。** 跨方法比较若各自用自己的 `S` 合并 GT，
   参考随方法漂移，表内数字不可比。例外只覆盖方法自身的前向与训练。

## 未做的事

1. **不迁移任何存量项目。** `audit` 只报告，不改文件；迁移由用户按项目单独授权。
2. **不做内容语义检查。** 路径合规不等于科学合法性，也不等于证据资格。
3. **不改 `state_check.py` 的 S1—S7 / V1—V24**，不改 schema，不改协议命名空间与状态路径。
4. **不把 `layout_guard.py` 设成唯一门禁。** 它是 `release_check` 之外的项目侧工具，
   在项目仓库里运行，不进入 Skill 自身的发布闸门语义。

## 升级注意

- 已有 `AGENTS.md` 的项目不需要立即重写：先跑 `audit`，`block` 项逐条核对，
  `warn` 项记入根 `INDEX.md` 的 Warnings。
- 采用新模板是**替换内容**，不是迁移目录；替换前把项目独有条款保留到冻结协议或
  `docs/dev/`，不要丢差异。
- MRI 项目继续用 `mri_training.py sync-agents` 维护受管块，不手改。
