# v2.3.0 — MRI reconstruction training policy

**Date:** 2026-11-18
**Tag:** `research-lifecycle-protocol/v2.3.0`

## Training and evaluation

- Use the dataset's prepared train, val and test directories. Score the full val set for model selection and the full test set for the final report. Use volume-level grouping only when the network reconstructs an entire 3D volume at once.
- Select `best_val` by a prespecified PSNR or NMSE on full val GT for both supervised and self-supervised training. Self-supervised updates can use the mask-split loss within the training information boundary. Model selection excludes mask-split losses and measurement residuals.
- Preserve the prepared dataset's spatial dimensions and use its per-slice masks. By default, 1D Cartesian masks undersample along columns.
- Keep resumable `best_val` and `latest` checkpoints. Report the training budget, optimizer, learning rate, inputs and outputs before launch.
- Use CSM-combined complex images as references and predictions. Compute NMSE in the complex domain and PSNR and SSIM on magnitude images.

## Upgrade

MRI bootstrap syncs the mandatory [training rules](../../domain-profiles/mri-reconstruction/training-policy.md)
to project-root `AGENTS.md`. Existing projects must sync the same rules before
starting training. Managed training validates the rule section, full-val GT
selection declaration and the report fields in the bound configuration at issue
and launch. Projects verify their loader, checkpoint and metric implementation.

Report conflicts with existing project rules, data or frozen protocols before
running affected training. Existing historical results and frozen protocols remain
readable for audit. Protocol identifiers and project control-root paths retain
their existing versions.
