# Research Lifecycle Protocol v2.1.1 — Storage Migration Safety Patch

**Release date:** 2026-11-10（本分支验收日期）· **Component:** `research-lifecycle-protocol/` · **Planned tag:** `research-lifecycle-protocol/v2.1.1`
**Status:** 在 `research-lifecycle-protocol/dev` 分支验收；tag 随合并进 `main` 时创建。
**Base:** v2.1.0（tag `research-lifecycle-protocol/v2.1.0` @ merge commit `cdabc9a`）。

---

## 1. What this release is

v2.1.1 是 v2.1.0 存储迁移的**定向安全补丁**，不改变 R0–R14、Research State、CIE、
TAG、MMS、I2M、Scheduler 或任何科研语义。它修复「迁移可能静默丢数据 / 回滚可能覆盖新工作」
这一类事务完整性问题。

## 2. 修复摘要

| 缺陷 | 修复 |
|---|---|
| 迁移没有维护锁，两个迁移可并发 | `.rlp-migration/control.lock` + `flock` 独占；整个事务持锁 |
| 运行期写入者不感知迁移 | RLP 写入入口持共享锁：research loop / reconcile / 受管执行 / 认知投影 / STATUS / Cold Handoff；迁移期间返回 `MAINTENANCE_IN_PROGRESS` |
| 源目录在复制期间变化可静默丢失 | 旧根在**预检 / 备份后 / staging 后 / cutover 前**四次快照比对；变化即 `SOURCE_CHANGED_DURING_MIGRATION`，保留旧根与备份 |
| 回滚只看 `research-state.json` | 记录完整 durable manifest（类型/大小/SHA-256/符号链接/权限），回滚比对**整个控制平面**：Scheduler、TAG、轨迹、收据、新增/删除文件、符号链接变化全部拒绝（`ROLLBACK_REFUSED_NEW_WORK`） |
| 项目根文档在 cutover 前被改写 | 改写只在 staging 副本；cutover 成功后逐文件原子替换并写 journal；中途失败按 manifest 恢复原字节 |
| journal 静默跳过坏行 | 损坏即 `JOURNAL_CORRUPT`，保留原文件，不做推断 |
| `recover` 自动删 staging | 默认只读；只有「staging 与源快照一致」时 `--apply` 才清理；不唯一即 `manual` |
| cutover 与归档之间是双根暂态 | 显式状态 `new_root_installed` / `legacy_archived`；`recover --apply` 在两侧都与记录 manifest 一致时完成归档 |
| verify 在目标目录重新生成 manifest 即宣布成功 | verify 以迁移期间记录的 manifest 为基准逐项比对（新根、备份、文档、科研指纹、哈希链） |
| 备份可落在源目录内 / 跟随符号链接 | 备份边界检查（旧根/新根/工作目录/归档内部一律拒绝）；符号链接按链接复制、不跟随、不读取目标内容，越界链接记录告警 |
| 无协作停写确认即可迁移 | `--apply` 必须同时给 `--assume-writers-quiesced`，否则拒绝无人值守迁移 |

## 3. 维护锁的覆盖边界（重要）

**受保护（协作）**：RLP 自身的控制平面写入入口——`preset_router.run_preset`（含
research-loop 与全部 Preset）、`operational_reconcile.reconcile`、
`experiment_execute issue/run`、`cognition build`、`render_status` 写入、
`legacy_handoff take`。这些入口在迁移期间拒绝写入并返回可诊断状态。

**不受保护（非协作）**：DSH Research Mesh worker、后台训练/结果收集进程、直接读写
控制根的第三方脚本。它们不获取 RLP 维护锁，**工具无法证明其静止**。因此迁移要求
`--assume-writers-quiesced` 作为操作者确认，并在报告中明确列出这些写入者。
RLP 不声称实现了跨系统强制互斥。

## 4. 回滚语义

`rollback` 是**灾难恢复**，不是恢复科研执行的许可。成功回滚后项目回到
`MIGRATION_REQUIRED`：旧根重新成为迁移来源，正式运行仍需重新完成安全迁移。
迁移后**任何** durable 写入都会使回滚被拒绝并列差异；工具绝不自动删除新增科研产物。

## 6. Compatibility

- 机器协议命名空间（`research-idea-pipeline/...@1`）冻结不变。
- 迁移 journal 升到 `research-idea-pipeline/migration-journal@2`；v2.1.0 的
  journal 记录仍可读（缺失字段按旧语义解释并在报告中标注）。
- 旧项目仍只能只读访问；正式运行需要迁移。
