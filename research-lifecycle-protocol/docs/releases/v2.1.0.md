# Research Lifecycle Protocol v2.1.0 — Project Storage Unification & Safe Migration

**Release date:** 2026-11-10（本分支验收日期）· **Component:** `research-lifecycle-protocol/` · **Planned tag:** `research-lifecycle-protocol/v2.1.0`
**Status:** 在 `research-lifecycle-protocol/dev` 分支验收；tag 随合并进 `main` 时创建（annotated）。
**Base:** v2.0.1。

---

## 1. What this release is

统一所有科研项目的机器状态存储规范：**`.research-lifecycle-protocol/` 成为唯一运行时
控制根**；旧根 `.research-idea-pipeline/` 降级为迁移来源。提供可预检、可验证、可回滚的
正式迁移工具。这是**项目控制平面存储规范升级**，不是 Research State Schema 的重新设计。

## 2. Storage matrix（运行行为矩阵）

| 项目状态 | 状态令牌 | 正常运行行为 |
|---|---|---|
| 两个目录都不存在 | `NEW_PROJECT` | 初始化使用新目录 |
| 只有新目录（有可识别内容） | `READY` | 正常加载和执行 |
| 只有新目录（空/不可识别） | `INVALID_STORAGE_ROOT` | 禁止静默修复或重建 |
| 只有旧目录 | `MIGRATION_REQUIRED` | 暂停正式运行，先迁移 |
| 新旧目录同时存在 | `AMBIGUOUS_STORAGE_ROOT` | fail closed |

`MIGRATION_REQUIRED` 是工程控制平面状态：不计入 Failure Memory、不触发科学重规划、
不重启实验。写入入口闸门：Research Loop（`project_context`）、`operational_reconcile`、
`experiment_execute issue/run`、`cognition build`、`render_status --root`、
`legacy_handoff take`；只读工具（`state_check`、`legacy detect`、迁移工具）不受限。

## 3. 迁移工具

| 命令 | 作用 | 失败语义 |
|---|---|---|
| `inspect --project P` | 只读预检：矩阵、durable 清单（SHA-256）、科研资产指纹、路径依赖分类（可重写运行时文档 vs 永不重写历史记录）、写入者劝告 | 损坏 layout → exit 3 |
| `plan --project P --backup-root B` | 迁移 ID、备份目的地、磁盘容量检查、重写策略；**只读** | 旧 State 损坏 → `ready_to_migrate: false` |
| `migrate --project P --backup-root B --apply` | 验证备份 → 同盘 staging → staging 指纹校验 → 显式 manifest 记录的运行时文档重写（opt-in）→ 原子 rename 切换 → 旧根改名出解析器命名空间 → verify | 备份失败/校验失败/staging 校验失败/切换失败均不丢数据，journal 可追踪 |
| `verify --project P --migration-id ID` | 矩阵 = READY、逐路线 state gate、决策轨迹/TAG 链校验、journal 终态检查 | 任一问题 → exit 3 |
| `rollback --project P --migration-id ID` | 恢复归档旧根 + 重写文件原字节；迁移后产生新科研写入时**拒绝回滚** | REFUSED |
| `recover --project P` | 中断检测：清理 staging 或指向 verify（孤儿 cutover） | — |

保证：不重新 Bootstrap；不重写历史记录（冻结预注册/证据/事件链/收据字节不变）；
幂等（已迁移项目再跑 migrate = ALREADY_MIGRATED）；备份逐项 SHA-256 校验后才切换；
断电/中断由 journal + recover 处理；跨文件系统备份为复制+校验（不谎称原子 rename）。

## 4. Verification（如实分级）

| 等级 | 状态 | 依据 |
|---|---|---|
| L1 实现有效性 | **已验证** | 17 个迁移工具测试（完整两路线迁移、指纹一致、哈希链字节不变、预算/Schema ID 不变、幂等、回滚守卫、6 类故障注入）+ 23 个存储矩阵/身份测试 + 7 个静态规范测试 |
| L2 运行有效性 | **部分验证** | 新项目 Bootstrap E2E（只建新根、loop 正常启动）；迁移后 Resume E2E；Domain Profile 随控制根迁移并被新根加载；运行入口闸门经真实入口测试 |
| L3 科研有效性 | **NOT YET VALIDATED** | 存储迁移不改变科研事实（由指纹与哈希链机械保证）；科研有效性仍以 v2.0.1 的 replay 接口与未来盲化 A/B 为准 |

## 5. Compatibility

- 机器协议命名空间（`research-idea-pipeline/...@1`）**冻结不变**；迁移不改写任何
  `_schema` 值。
- 旧项目的只读兼容检查（`state_check`、`legacy_handoff detect`、迁移工具）继续可用；
  但旧根不再承担日常运行。
- 既有项目 **不会** 被自动迁移；迁移必须由用户对具体项目显式执行（第九部分纪律）。
- DSH Research Mesh：外部插件若硬编码旧路径，需要协同修复（见 identity 文档 §3 的
  协同修复需求清单）；RLP 侧契约已更新为新控制根。
