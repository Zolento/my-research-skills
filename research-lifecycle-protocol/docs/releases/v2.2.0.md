# v2.2.0 — Context & Architecture Optimization

**Release date:** 2026-11-10
**Tag:** `research-lifecycle-protocol/v2.2.0`

## 这一版改了什么

把 RLP 从「Agent 每次要读一大套科研规章的 Skill」改成「以精简协议启动、按任务恢复知识、
依靠既有工具执行科学约束的科研运行系统」。

**减的是加载量，不是约束。** 本版没有改变任何一条科研规则的含义：R0—R14 阶段数不变、
八类 canonical 对象不变、Evidence ID / XID / Claim ID 不变、16 个 Preset 身份不变、
Domain Profile 的显式激活不变、PEIG / AALG / R8 冻结 / R10 修复门 / R14 决策语义全部不变。

## 主要变化

### 1. `SKILL.md` 从 156 KB 降到 27 KB（−83%）

`SKILL.md` 重构为 L0 常驻核心，只保留四件事：进哪道门、哪些约束不能破、这一轮加载什么、
门禁在哪里。逐阶段读写表、完整资源索引、设计依据、维护自检、执行自检完整版、I2M 细节、
锚点体系细节全部下沉为可定位的 L2 参考。

**取代表中的一项检查。** 原先 `release_check` 比对 `SKILL.md` 与 `research-state-policy` §5
的读写单元格。L0 不再复制这些单元格，因此该比对改为
`policy ↔ phase-*.md`（14 行逐格），并新增 `step_stage_index_parity`：
L0 的阶段索引必须覆盖 R0—R14 且**不得重新长出读写列**。
保护对象从「重复的副本」变成「不重复的阶段集合」，覆盖范围反而增加（现在包含 R1）。

### 2. 三级上下文（L0 / L1 / L2）

| 级 | 内容 | 何时 |
|---|---|---|
| L0 | `SKILL.md` | 每次激活 |
| L1 | `shared-contract.md` + 选中的**一个** Preset + 本任务必需 references + Research Context Packet | 每次任务动作 |
| L2 | 完整 policy / 数学推导 / 专项审查 / 异常处理 / Replay | 按需 |

实测（12 个场景）：每次调用的协议上下文平均从 129,426 字符降到 37,855 字符（−71%），
工具调用从 4.08 次降到 3.42 次，**没有任何场景需要读更多文件**。
完整数据见 [../context-benchmark.md](../context-benchmark.md)。

### 3. 机器可读的上下文依赖声明

`preset-registry.json` 的每个 Preset 新增 `context` 块：`required` / `conditional` /
`deep_references` / `domain_extensions` / `forbidden`。无预设的入口（`start-project`）
走 `entry_context`。

新增 `scripts/context_planner.py`：

- `plan()` 是纯函数，同样的输入给同样的 `plan_digest`；
- 七个加载状态 `loaded` / `required` / `conditional` / `referenced` / `available` /
  `not_loaded` / `blocked_missing`；
- `execute()` 才真正读盘并填 `loaded`；缺必需项即 `can_proceed=false`；
- **超预算不静默截断**：安全约束、权限边界、冻结条件、会改变本轮决定的关键反例永不截断，
  未覆盖项列入 `uncovered`；
- 四类预算分开（protocol / research / evidence / tool），不合成一个长度。

### 4. `loaded` 与 `referenced` 的语义修复

`preset_router.load_preset_context()` 原先把 `scripts/*.py` 的路径名放在
`loaded_references` 里。**返回路径列表不等于规则已进入模型上下文。**
现在 `loaded` 只记实际读取并返回正文的文件，脚本引用改名 `referenced_scripts`，
并附 `load_semantics` 说明。

### 5. 章节级加载

新增 `scripts/section_index.py` 与 `references/section-index.json`（66 份文档、977 个章节）。
章节 id 由**标题文本** slug 化，不依赖行号；索引可从正文重新生成，`check` 会比对，
正文改了索引没重建即判红。

`context_planner` 支持 `"references/x.md#章节查询"` 形式的依赖声明。
`research-recovery`、`context-drift-recovery` 等已用它对 50 KB 的
`research-state-policy` 做精确取用。**章节查询未命中时不会退化为整文件加载**，而是阻断。

### 6. Research Context Packet

新增 `scripts/context_packet.py`：面向一次科研决策的 13 项最小上下文，绑定
`state_version` / canonical digest / 相关 evidence digest / Skill 版本 / Domain 配置摘要。
`verify()` 检测失效，并明确禁止三件事：把旧摘要当新事实、清空 Research State、
重新 Bootstrap。

它**不是**第九类对象，**不是**第二套研究记忆，**不是**授权来源。

### 7. 子 Agent 最小任务契约

新增 `scripts/subagent_context.py` + `references/subagent-context.md`：按角色
（`literature` / `theory` / `experiment` / `assurance` / `discovery`）裁剪上下文，
并用五个机械不变量保证**裁剪不扩张权限**：能力必须是父级子集、`write_canonical` 只属于
主 Agent、任何角色不得 `modify_anchor`、执行角色必须要求 manifest 与批准、
`never` 列表不得为空。

实测子 Agent 上下文从 123,449 字符降到 16,881 字符（−86%）。

### 8. 实测基线工具

新增 `scripts/context_profile.py`：把「上下文成本」拆成六层分别测量（static / loaded /
visible / duplicate / estimate / calls），每一层单独声明测到了什么。
它**不产出真实 token 数**（仓库内没有 tokenizer），只产出精确字符数与带方法名的估算，
并拒绝把估算和实测混在同一列。

## 兼容性

- Skill 名称仍为 `research-lifecycle-protocol`。
- 机器协议命名空间仍为 `research-idea-pipeline/...@1`（新增的三个 schema 同样使用该前缀）。
- 运行时状态根仍为 `<project>/.research-lifecycle-protocol/`。
- **不需要迁移任何项目的 canonical state。** 新增的只有一个派生索引
  `references/section-index.json`，删除后可重新生成。
- 已安装的旧版本无需改动数据；升级只替换 Skill 文件。

## 未完成与限制

1. **L0 目标 10—15 KB，实测 27.5 KB。** 未达标，理由见
   [../context-benchmark.md](../context-benchmark.md) §5。没有为达标删除必要规则。
2. **没有真实 tokenizer，也没有 Harness 请求记录**，所有 token 数字是启发式估算。
   唯一的 `visible` 层数据是一次单次 Harness 观测（注入 154,495 bytes，模型可见 84,026）。
3. **Prompt Cache 未验证**，不声称任何缓存收益。
4. **L3（真实科研 A/B）未执行。** 行为回归与 Replay 只支持 L1/L2 结论。
5. **未修复、已记录**：`references/` 中仍有约 20 处 `.research-idea-pipeline/routes/...`
   写法（v2.1.0 已把运行时根改为 `.research-lifecycle-protocol/`），涉及 9 个 phase 文档。
   这些属于规范漂移而非本轮上下文问题，改动会触及科学落盘路径，留待单独一轮处理。
6. **未修复、已记录**：`roles.md` 的六个攻击面与 `invocation-prompts` / `phase-r7` 的
   八个攻击面表述不一致。属于科学规则冲突，不是上下文问题，本轮不动。
