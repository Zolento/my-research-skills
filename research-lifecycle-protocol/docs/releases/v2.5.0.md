# v2.5.0 — 中文科研文档的类型感知质量检查

日期 2026-11-21。目标 tag `research-lifecycle-protocol/v2.5.0`（合并进 `main` 后打）。

## 为什么改

15 份真实 route F 文档（F000—F015，约 477 KB）暴露了四个问题：

1. **职责混杂。** `F010-theory.md` 有 1732 行、66 个标题，同时装文献综述、定理、方向分析、
   独立审查、研究决策与数值探针。长不是错，找不到结论才是。
2. **运行细节侵入正文。** `F007-discovery.md` 的「限制与未决」一节把文件哈希、mtime、
   并发写入与科学结论写在同一处。这些材料属于审计，不属于研究正文。
3. **冻结语义含糊。** `F005`/`F008` 正文讲冻结预注册，frontmatter 却是 `draft`。这不一定错，
   但读者分不清哪份是权威来源。
4. **并行会话抢文档 ID。** `F010` 原本编到 `F009`，落盘时才发现另一个会话已经占用。

同时，句子层 linter 把这 15 份文档报成 658 条「硬违规」，其中绝大多数是合法的技术长句。
把这种噪声当门禁，只会训练写作者绕过检查。

## 改了什么

### 一个协调层，不是第二套体系

新增 `scripts/doc_quality.py`。它编排已有的 `ste_lint_zh.py`（句子形式）、
`layout_guard.py`（路径与文档 ID）与 Markdown 解析，自己不保存任何文档事实。

```bash
doc_quality.py check --path FILE [--root 项目]
doc_quality.py check --changed | --staged [--json]
doc_quality.py compare --before OLD --after NEW --intent prose-only
doc_quality.py selftest
```

### 三档分级

| 档 | 内容 |
|---|---|
| **BLOCK** | 文档 ID 冲突、frontmatter 与文件名或路线不一致、坏相对链接、坏页内锚点、未闭合围栏、预注册摘要不符、声明只改语言却改了受保护内容 |
| **WARN** | 长文缺导航、运行记录与科学结论同处一节、近重复段落、执行细节排在结果之前、研究正文混入决策与探针、句长、分号、被动语态 |
| **REVIEW_REQUIRED** | 因果是否过度归因、定理条件是否齐全、冻结语义是否有歧义、旧控制根引用是否仍有效、预注册不在可解析位置 |

WARN 与 REVIEW_REQUIRED 不会被提升成科研状态 BLOCK。

### 纯语言修改的内容保护

`compare --intent prose-only` 比对公式、带单位数值、指标名、实验 ID、DOI 与 arXiv、
摘要值、路径、情态与限定、数据范围。任一类变化都判 BLOCK 并列出增删。
任务本身是科学修订时用 `--intent scientific-change`；已有授权时加 `--allow-scientific-change`。

### 增量检查

`--changed` 与 `--staged` 只报新增或恶化的问题，未改动的存量问题不会因新政策被拦。
`--staged` 读索引内容，不读工作区里可能更新的版本。

### 文档 ID 独占创建

`layout_guard.py` 增加 `doc-ids` 与 `allocate`：前者只读报告下一个可用 ID，
后者用 `O_CREAT|O_EXCL` 建骨架，撞车自动换号。不新增 ID 登记表。

### 严重度对齐

`ste_lint_zh.py` 把分号、句长、名词化标成 hard；整篇文档尺度上这些改判 WARN。
保留 hard 的只有套话（`empty-phrase`）。宣传词降为 WARN，因为词表里的「闭环」
在 MRI 与 ADMM 语境是术语。

## 未做的事

1. **不改科研机制。** R0—R14、Evidence Qualification、Outcome 与执行门禁、 Research State
   schema、真实实验冻结文件，全部未动。
2. **不做对话回复 linter，不做 Hook。** 三家的回复机制保持不变。
3. **不自动改文档。** 检查器只报告；相似段落、旧路径、冻结字段都要人来处置。
4. **不判断科学正确性。** 证明是否正确、机制归因是否成立、引用是否真支持主张，
   只能 REVIEW_REQUIRED。

## 实测

15 份真实文档：句子层原报 658 条 hard；`doc_quality.py` 判 2 条 BLOCK，
均为真实存在的跨路线裸文件名链接（`F008` 引用 routeE 的 `E027` / `E031`），
其余转为 315 条 WARN 与 4 条 REVIEW_REQUIRED。识别到的问题包括 `F007` 的运行记录混写
与 `F014` 的执行细节前置。

## 升级注意

- 项目若已挂提交前钩子，加入 `doc_quality.py check --staged`；没有钩子就先手动跑。
- 首次在存量项目上运行会看到大量 WARN。先从 BLOCK 与 REVIEW_REQUIRED 处理，
  WARN 按文档类型分批改，不要为了清零而删内容。
- 旧控制根路径引用报 REVIEW_REQUIRED，不报 BLOCK：历史证据的旧路径可能是合法的。
