# Historical replay fixtures

Synthetic replay cases. They are **not** results from a real study and must never be cited as
scientific evidence. They exist so the discovery-replay framework can be exercised offline,
through the same gates as the ordinary pipeline.

| Path | Role |
|---|---|
| [adversarial/](adversarial/) | Fourteen adversarial situations, one per failure mode the specification names |

Each case carries a `visible` section — the state, revisions, scheduler and observation packet
as they were at the time — and a `hidden` section with later results and the reference answer.
Only the visible section reaches a runner.

```sh
python3 scripts/research_replay.py suite  --dir examples/replay/adversarial --runs 2
python3 scripts/research_replay.py ablate --dir examples/replay/adversarial --runs 2
python3 scripts/research_replay.py smoke  --work /tmp/cie-smoke
```

The cases are generated by `research_replay.adversarial_cases()` and written with

```sh
python3 scripts/research_replay.py adversarial --write examples/replay/adversarial
```

so the shipped files and the in-code suite cannot drift apart; a test asserts they match.

See [discovery-replay.md](../../references/discovery-replay.md) for the case schema, the leak
guard, the metrics, the ablation arms and what has **not** been verified.
