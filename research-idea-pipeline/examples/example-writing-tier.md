# 示例：受控中文两档对照（同一段内容怎么改）

演示同一段 Mode D 叙事在「中文-顺」档与 **asd-ste100** 档下的形式差别。
**内容一个字不动，只改句子形式。** 这正是政策 §5「情态是内容」的落地写法。

---

## 1. 场景

取某 Mode D 叙事里的一段「方案概要」。它已通过默认档的机械闸门，
但离 asd-ste100 档还差一截。下面是同一段内容的两种写法。

## 2. 改前：默认档（中文-顺）合格

```
概念上，这个方案把重建问题写成一个稀疏先验下的优化问题。
我们用展开网络近似这个优化过程，并在 fastMRI 上验证了它。
四倍加速下，它比基线高 1.8 dB。
我们核对了消融设置，也检查了梯度回传路径。
不过，这个提升可能部分来自更强的正则化，初步结论仍需复核。
```

## 3. 改后：asd-ste100 档合格

```
本方案把重建写成稀疏先验下的优化。
展开网络近似这个优化。
我们在 fastMRI 上验证它。
四倍加速下，它比基线高 1.8 dB。
我们核对了消融设置。
我们也核对梯度回传路径。
不过，这个提升可能来自更强的正则化。
初步结论仍需复核。
```

## 4. 逐句差别

| 改前 | asd-ste100 档报告 | 处置 |
|---|---|---|
| 概念上，这个方案把重建问题写成一个稀疏先验下的优化问题。 | `long-sentence`（26 字） | 压到 25 字内，删掉「概念上」这类铺垫 |
| 我们用展开网络近似这个优化过程，并在 fastMRI 上验证了它。 | 无报告 | 仍拆句：§2 要求一句一动作，linter 不查「并」字句 |
| 我们核对了消融设置，也检查了梯度回传路径。 | `synonym-rotation`（核对 / 检查混用） | 拆句，并把「检查」统一成「核对」 |
| 不过，这个提升可能部分来自更强的正则化，初步结论仍需复核。 | `long-sentence`（26 字） | 拆成两句，「可能」「初步」原样保留 |

**两条注意：**

1. 「一词一义」在 asd-ste100 档下是**硬规则**。同一动作全篇只留一个动词，
   所以「核对 / 检查」必须收敛成一个。
2. **第 2 行没有任何 linter 报告，我们照样改了它。** linter 不查「并」「同时」
   这类串联，所以「零违规」不等于「一句一动作」达标（政策 §7 已声明这一点）。

## 5. 反面教材：过闸不等于没改内容

```
❌ 实验可能受批次效应影响。   →   实验受批次效应影响。
❌ 结果初步支持该假设。       →   结果支持该假设。
```

上面两种改法**都能通过 linter**（句子更短，也没有禁用词），但**都改了结论**。
linter 查不出这一层，所以政策把情态单列为**内容**，并禁止为了压句长而删它。

## 6. 建议类规则：asd-ste100 档下升为硬

```
该系统被重写成端到端流程。           → passive-voice（说清施事，改用主动）
该方法在若干数据集上验证过。         → vague-word（给出数量或范围）
结果提升明显 —— 这一点值得注意。     → dash-join（拆句，删套话）
结果提升明显,超过基线。            → halfwidth-punct（改全角）
任务已经完成了。                     → compound-aspect（改为「任务已完成」）
```

默认档里这几条只报告。asd-ste100 档下必须逐条处置，但**脚本不会因此失败**
（它的退出码只看硬规则）。

**政策因此写明：不要用退出码 0 冒充 asd-ste100 合规。**
本档真正的判据是硬违规 0，**加上**上面五条人工逐条确认。

## 7. 怎么跑

```bash
# 默认档：本文件必须硬违规 0（§8 D6 的仓库级闸门）
python3 scripts/ste_lint_zh.py --disable synonym-rotation examples/example-writing-tier.md

# asd-ste100 档：只对「当次调用产出」跑，不追溯扫本文件
python3 scripts/ste_lint_zh.py --max-chars 25 <改后的文件>
```

**本文件自身的口径：** 上面几段示例文本都在围栏里，围栏不参与扫描
（linter 自检里有「代码块里的分号不算」）。所以本文件的散文部分必须干净。
它是**给人照抄的**，正文示范旧写法正是 `SKILL.md` §8 A3 点名的历史坑。
