# 顶会创新性标准（锚定用）

所有创新性判定**必须**引用下表中的具体标准，不得只写"新颖性不足 / 很新"。

---

## 0. 两角度评价框架（所有会议审稿人强制）

**每个会议审稿人（R-CVPR / R-ICML / R-NeurIPS / R-MICCAI）都必须先从理论角度与应用
角度综合评价，再叠加本会议的特性判定。只写一个角度 = 评审不合格。**

| 角度 | 看什么 |
|---|---|
| **理论角度** | 命题 / 假设 / 推导是否成立；形式化是否完整；有无未证明的跳跃；理论贡献的深度与新颖性。**偏应用的工作也要说清理论侧是否成立、缺哪一步形式化。** |
| **应用角度** | 能否落地；实用性与效率；影响面；可验证性；与真实工作流的兼容性。**偏理论的工作也要说清应用侧的可达性与限制。** |

**再叠加本会议的特性判定**——这是"突出各自会议特性"的落点，**必须显式引用**下面对应
章节的标准条目：

| 审稿人 | 会议特性判定 |
|---|---|
| R-CVPR | 方法落地与经验验证是否充分；是否触发"新颖性谬误"（§1） |
| R-ICML | 是否属于广义原创性（创造性组合 / 新领域 / 移除限制性假设）；理论深度与假设必要性（§2） |
| R-NeurIPS | 贡献类型判定；洞察是否超出"工程组合"；Concept & Feasibility 门槛（§3） |
| R-MICCAI | 临床相关性；验证严谨性（多中心 / 外部验证、按受试者分组、统计检验）（§4） |

**输出要求：** 书面意见必须**显式分三段** —— `理论角度` / `应用角度` / `会议特性判定`；
Mode D 与 Mode E 的评分维度也按该结构给出（见 [roles.md](roles.md) §1、§5、§6）。

> ⚠️ **两个角度都要有实质内容。** 用"理论上没问题、应用上很有价值"这类空话充数，
> 等同于没写。每条判断必须落到**具体的命题、假设、实验或工作流环节**上。

---

## 1. CVPR

| 维度 | 标准 |
|---|---|
| 首要 | **方法落地与经验验证优先**。 |
| 警示 | **警惕"新颖性谬误"**：不能仅凭"看起来新"给正面，也不能仅凭"有人做过类似的"给负面。 |
| 断言纪律 | 断言"已有类似工作"**必须附具体引用** `[作者, 会议/年份]`。 |
| 正面评审义务 | **必须指出最有趣的新颖之处**，而非泛泛称赞。 |

## 2. ICML

| 维度 | 标准 |
|---|---|
| 首要 | **广义原创性**（broad originality），不局限于"全新方法"。 |
| 鼓励的原创性来源 | 现有想法的**创造性组合**；**应用到新领域**；**移除限制性假设**。 |
| 断言纪律 | 原创性被否定时**必须提供精确先前工作引用**。 |
| 附加 | 理论深度；结论的紧性与假设的必要性。 |

## 3. NeurIPS

| 维度 | 标准 |
|---|---|
| 首要 | **区分五种贡献类型**：General / Theory / Use-Inspired / Concept & Feasibility / Negative Results。 |
| 门槛 | **Concept & Feasibility 类**的重要性与原创性门槛**更高**。 |
| 原创性来源 | 可来自**新见解、新理解、新性质揭示**，不要求新方法或 SOTA。 |
| 附加 | 洞察深度；结论可迁移性。 |

---

## 4. MICCAI

| 维度 | 标准 |
|---|---|
| 首要 | **临床相关性与验证严谨性并重**。方法再新，若临床问题不成立或验证不可信，仍不成立。 |
| 警示 | **警惕"换数据集 / 换 backbone"式工程增量**；也警惕**单中心小样本结论外推**。 |
| 数据纪律 | 必须说明数据来源与使用许可 / 伦理审批；必须声明划分是**按病人 / 受试者分组**（防同一受试者同时出现在训练与测试集造成泄漏）。 |
| 验证义务 | 关键结论必须给出**统计检验与不确定性**（置信区间 / 误差棒）；有条件时应有**多中心或外部验证**，做不到须说明原因。 |
| 临床意义 | 改进必须落到**临床可解释的收益**，不能只报"指标 +0.5%"；应说明与临床工作流的兼容性。 |

> ⚠️ **适用性：** R-MICCAI 的 `临床相关性` 与 `验证严谨性` 是**条件性维度**——仅当工作
> 具有临床 / 医学影像属性时才打分；否则输出 **"不适用"**，且这两个维度**不进入中位数
> 向量**（与 S-Repro 的处理一致，见 [roles.md](roles.md) §6）。

## 5. 贡献类型标注规范

任何 Mode 输出的贡献点都必须标注类型。两种标注体系二选一，**全篇保持一致**。

**按 NeurIPS 五类：**

| 类型 | 含义 | 典型证据 |
|---|---|---|
| General | 通用贡献 | 方法 + 大规模经验验证 |
| Theory | 理论贡献 | 定理、证明、界 |
| Use-Inspired | 应用驱动 | 面向实际任务/领域的结果 |
| Concept & Feasibility | 概念与可行性 | 概念验证、可行性证据（门槛更高） |
| Negative Results | 负结果 | 严谨的否证与失效分析 |

**按通用四类：** 方法 / 理论 / 实证 / 问题定义。

### 5.1 方法来源标注（原创 / 部分原创 / 迁移）

**贡献类型说明「这是什么贡献」；方法来源说明「这个方法是哪来的」。两者都必须标。**

| 标注 | 含义 | 判据 | 对创新性的影响 |
|---|---|---|---|
| **原创** | 核心机制由本工作提出 | 指出最接近先前工作 + **机制层面**的差异 | 正常计入创新性 |
| **部分原创** | 核心机制部分来自既有工作，但有关键改造 / 新组合 / 新性质 | 写明**改了哪一条** + 改造带来的新性质 | 创新性取决于改造是否触及新结构性质 |
| **迁移** | 把其他领域 / 任务的既有方法搬来，机制不变 | 写明**来源领域 + 迁移合法性依据** | **迁移本身不算增量**；只有证明"迁移带来新性质"才构成贡献 |

**硬性要求：**

- **不得留空、不得模糊。** "受 X 启发""结合了 A 与 B"都不是标注。
- **迁移不得包装成原创。** 这属于夸大（违反 Mode D §D2.4 包装纪律）。
- ICML 视角下，`迁移` 唯一可能的出口是 §2 的「**应用到新领域**」——那需要证明
  迁移的**合法性**（假设如何修改）与新领域中的**新性质**，而不是"拿来就用"。
- Mode E 见 §7：`迁移` 且无新性质 → **复现风险高**。

## 7. 复现风险判定标准（Anti-Reproduction，Mode E 强制）

> **目的：避免把一个"做得很扎实的复现"当成贡献送审。** 技术正确 ≠ 可发表。

### 7.1 六项检查

| # | 检查项 | 判定 |
|---|---|---|
| 1 | 是否存在**可一对一对应**的已有方案（问题、机制、结论三层都对应）？ | 有 / 部分 / 无 |
| 2 | 本方案相对它的增量是**设计改变**，还是仅**实现优化/超参调整**？ | 设计改变 / 实现优化 / 无实质增量 |
| 3 | 增量是否触及**新的结构性质或理论条件**？ | 是 / 否 |
| 4 | 若把已有方案原样重跑，本方案的核心声称是否仍成立？ | 是 → 风险高 / 否 |
| 5 | 是否只是把已有方法**换数据集 / 换 backbone**？ | 是 → 风险高 / 否 |
| 6 | 最接近工作的作者会认为这是**独立贡献**还是**自己的后续工作**？ | 独立 / 后续 / 复现 |

### 7.2 等级与后果

| 等级 | 判据 | 后果 |
|---|---|---|
| **低** | 设计层面增量，触及新的结构性质或理论条件 | 可继续 |
| **中** | 增量偏实现层，但问题设定或评估口径不同 | 必须补强贡献声称或改变定位 |
| **高** | 可一对一对应且无实质设计增量 | **列为致命风险；总体判定不得为"高"** |

### 7.3 与各顶会标准的对应

- **CVPR：** 警惕"新颖性谬误"——既要防止把复现当新工作，也要防止仅因"有人做过类似的"
  就否定；断言复现**必须附具体引用**。
- **ICML：** 复现通常不构成"广义原创性"；但若增量属于**移除限制性假设**或
  **应用到新领域**，可重新定位为贡献（需明确写出被移除的假设）。
- **NeurIPS：** 若确实是复现，可考虑转为 **Negative Results** 或
  **Concept & Feasibility** 定位；但这两类的门槛与举证要求更高，不能当作"降级发表"。
- **MICCAI：** 只**换数据集或换中心**属于 MICCAI 明确警惕的工程增量；但若增量是
  **新的临床问题定义**或**新的验证协议**（如多中心外部验证），可重新定位为贡献。
  复现类工作在 MICCAI 同样要说明数据许可与**按受试者分组**的划分。

### 7.4 措辞门禁

- 复现判定必须达到 **L3 穷尽检索**并附负检索记录；否则只能写"据本次检索未见"，
  且**不得**断言"复现风险低"。
- 禁止把"我们的实现比原论文高 0.3%"当作独立贡献。

---

## 8. 禁止事项

- ❌ 不引用任何具体标准就给出创新性判定。
- ❌ 贡献点不标注类型。
- ❌ 未经 S-Lit 核实即使用"首次提出 / first to"。
- ❌ 以"没人做过"作为新颖性的唯一论据（需说明**为什么之前没人做**，见 Mode C §C3 第 4 节）。
- ❌ Mode E 结论卡片缺少**复现风险等级**。
