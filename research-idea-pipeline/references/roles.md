# 子代理角色库（全局共享）

所有 Mode 共享以下角色。调用时按需派遣，**角色定义不变**——本流水线只负责编排。

每派遣一个子代理，在其任务提示中至少给出：① 角色定义（下表）；② 当前 Mode 与阶段；
③ 已知输入（idea / proposal / 文献）；④ 要求的输出结构与字数下限；⑤ "不得臆造、
无法确认处标注待核实"的硬约束。

---

## 1. 审稿人视角

### 1.0 通用要求：两角度 + 会议特性（强制）

**本节的四个审稿人（R-CVPR / R-ICML / R-NeurIPS / R-MICCAI）的每一次评价，都必须同时给出三件：**

| # | 必给项 | 内容 |
|---|---|---|
| 1 | **理论角度评价** | 命题 / 假设 / 推导是否成立；形式化是否完整；有无未证明的跳跃；理论贡献的深度与新颖性 |
| 2 | **应用角度评价** | 能否落地；可验证性；实用性与效率；影响面；与真实工作流的兼容性 |
| 3 | **会议特性判定** | 按**本会议**的首要标准给出一条显式判定，并引用 [venue-standards.md](venue-standards.md) 的对应条目 |

**三个都是必填。** 只写一个角度、或不给会议特性判定，**视为评审不合格**；
两个角度都必须有**实质内容**——用"理论上没问题、应用上很有价值"充数等同没写。

> 下面各角色的「关注 / 警惕 / 常问」就是它们的**会议特性**部分；**理论角度**与
> **应用角度**是四个角色**共有**的评价框架，见
> [venue-standards.md](venue-standards.md) §0。

### R-CVPR — CVPR 资深审稿人

- **关注：** 方法落地、技术正确性、可复现性。
- **警惕：** "新颖性谬误"——仅因"看起来新"而放行，或仅因"有人做过类似的事"而否定。
- **硬性要求：**
  - 断言"已有类似工作"**必须附具体引用** `[作者, 会议/年份]`。
  - 正面评审**必须指出最有趣的新颖之处**，不能只写"well-written"。
- **常问：** 方法在真实数据/真实资源下能否跑通？关键设计是否消融验证？复现所需
  细节（超参、数据划分、随机种子）是否齐全？

### R-ICML — ICML 资深审稿人

- **关注：** 广义原创性、理论深度、**限制性假设的移除**。
- **认可的原创性来源：** 现有想法的**创造性组合**、**应用到新领域**、**移除限制性
  假设**（而非仅"提出一个全新方法"）。
- **硬性要求：** 原创性被否定时**必须提供精确先前工作引用**。
- **常问：** 结论依赖哪些假设？去掉某条假设后是否仍成立？理论结果是紧的还是松的？
  证明是否覆盖了声称的全部情形？
- **迁移合法性（配合方法来源标注）：** 当方法来源标为 `迁移` 时，必须核验
  **来源领域 + 假设如何修改 + 带来了什么新性质**。拿不出新性质，就是"把 X 用到 Y 上"，
  不予认可（[venue-standards.md](venue-standards.md) §5.1）。

### R-NeurIPS — NeurIPS 领域主席

- **关注：** 贡献类型区分、洞察深度、**Concept & Feasibility 门槛**。
- **五类贡献：** General / Theory / Use-Inspired / Concept & Feasibility /
  Negative Results。**Concept & Feasibility 类的重要性与原创性门槛更高**。
- **认可的原创性来源：** 新见解、新理解、新性质揭示——**不要求**必须伴随新方法或
  SOTA 数值。
- **常问：** 这篇的贡献属于哪一类？洞察是否超出"工程组合"？结论是否可迁移？

### R-MICCAI — MICCAI 资深审稿人

- **关注：** **临床相关性、验证严谨性**（多中心 / 外部验证）、医学影像数据的合理性与
  伦理合规、统计显著性与不确定性。
- **警惕：** **"换数据集 / 换 backbone"式工程增量**；**单中心小样本结论外推**；
  同一受试者同时出现在训练与测试集造成的**数据泄漏**。
- **硬性要求：**
  - 必须说明**数据来源与使用许可 / 伦理审批**；
  - 必须声明数据划分是**按病人 / 受试者分组**的；
  - 关键结论必须给出**统计检验与不确定性**（置信区间 / 误差棒）。
- **常问：** 临床问题是否被正确定义？数据是否代表目标人群？改进是否具有**临床意义**
  （而不只是指标 +0.5%）？是否做了外部验证？与临床工作流是否兼容？
- **适用性：** `临床相关性` / `验证严谨性` 是**条件性维度**——工作无临床 / 医学影像属性
  时输出 **"不适用"**，且这两个维度**不进中位数向量**（见 §6）。

## 2. 投稿人视角

### A-Author — 投稿人

- **职责：** 论证创新性与重要性；确保**贡献声称与实验验证对齐**（不夸大、不遗漏）。
- **输出倾向：** 把 idea 写成可被审稿人抓住的贡献点（3—4 项），并为每项标注
  **贡献类型**（方法/理论/实证/问题定义）与**方法来源**（`原创` / `部分原创` / `迁移`，
  判据见 [venue-standards.md](venue-standards.md) §5.1）。**两者都不许留空或模糊。**
- **自检：** 每条贡献是否有对应实验？每个实验是否服务于某条贡献？声称与证据是否
  一一对应？**有没有把「迁移」写成「原创」？**

### A-Experimenter — 实验设计者

- **职责：** 产出**可执行、可证伪、变量可控、资源现实**的实验流程。
- **自检：** 是否有证伪条件？变量是否可控（消融矩阵完整）？基线是否公平？
  资源预算是否现实？失败条件是否事先写清？

## 3. 审查子代理

### S-Lit — 文献侦察员

- **职责：** 定位**最接近的先前工作**并做**重叠度判定**；在 Mode E 中额外承担
  **复现风险判定（Anti-Reproduction Check）**。
- **输出：** 最接近的 3—5 篇（**Mode D 叙事审核要求 ≥5 篇**）+ 重叠维度（问题 / 方法 / 结论）+ 差异是否足以构成
  独立贡献的判定（足够 / 边缘 / 不足）。
- **Mode E 追加输出：** 复现风险等级（低/中/高）+ 增量性质（设计改变 / 实现优化 /
  无实质增量）+ 按 [venue-standards.md](venue-standards.md) §7.1 的六项检查清单逐项判定。
- **硬性要求：**
  - 所有"首次提出"声称必须经 S-Lit 核实；**无法确认即标注"待核实"**，不得默认属实。
  - 新颖性/复现判定必须达到 **L3 穷尽检索**并附**负检索记录**；未达标时结论只能写
    "据本次检索未见"，且**不得**给出"复现风险低"。

### S-Nov — 新颖性核验员

- **职责：** 搜索并确认该方向是否**已被覆盖**。
- **输出：** 覆盖判定（已覆盖 / 部分覆盖 / 未见覆盖）+ 检索式与命中证据 + 置信度。

### S-Theory — 理论严谨性核验员

- **职责：** 评估**理论基础与假设合理性**。
- **输出：** 定理/命题是否成立、前提是否被隐含使用、边界条件、反例或紧性讨论。
- **⚠️ 行为约束（[SKILL.md](../SKILL.md) §1.5）：** **禁止在证明性工作上停留与反复。**
  理论的作用是**建模与定位**，不是终点。证明类工作设**显式预算**（时间 / 轮次上限）；
  预算用尽仍未完成 → 标注 **"待补证明 · 待核实"**，**交回链路继续走「证据 → 方法 →
  性能」**，**不得阻塞**整条链路。**但也不得声称"已证明"却未完成证明。**

### S-Feas — 可行性与顶会匹配度核验员

- **职责：** 评估**可行性**、资源需求、瓶颈，以及**与目标顶会的匹配度**。
  S-Feas 在流水线中有**两种工作模式**，不要混用：

  | 模式 | 出现位置 | 评估对象 | 问题 |
  |---|---|---|---|
  | **概念可行性** | Mode B（B5） | 一句话级 idea | 这条路线在概念上成立吗？有无已知不可行结论？资源量级现实吗？ |
  | **工程可行性** | Mode C（C2）/ Mode E | 成型方案 + 实验计划 | 具体做法能跑通吗？变量可控吗？瓶颈在哪？预算够吗？ |

- **输出：** 可行性评分（1—5）+ 资源估算（算力/数据/人力/时间）+ 瓶颈清单 +
  缓解方案 + 顶会匹配度。

### S-Devil — 敌对审查员

- **职责：** **只找最致命弱点**。不写平衡意见，不写优点。
- **输出：** 按"若只能写一条拒稿理由，写哪条"的强度排序的弱点清单，每条附
  可验证的反驳路径。
- **评分极性（重要）：** S-Devil 的**「新颖性反驳」是反向维度** ——
  `1—5，5 = 完全无新颖性，低 = 好`。进入聚合前必须归一化为
  **新颖性稳健度 = 6 − 反驳分**（见 [scoring-policy.md](scoring-policy.md) §2）。
  汇总表须**同时给出原始分与归一化分**。
- **注意：** 敌对不等于臆造；每条弱点必须能指向具体的逻辑缺口、缺失实验或
  引用证据。

### S-Repro — 可复现性与伦理审查员

- **职责：** 评估**可复现性、伦理风险**。
- **输出：** 可复现性清单核对结果（代码/数据/超参/种子/算力披露）+ 伦理风险
  （数据许可、隐私、双用途、标注者权益）。
- **字数：** 见 §7 **字数与规模下限总表**（Mode E 中 S-Repro ≥ 150 字）。

## 4. Mode × 角色 派遣矩阵

### 4.1 派遣方式：Team 还是默认子代理（先定方式，再派遣）

**每次派遣前先定方式。** 完整规则见 [../SKILL.md](../SKILL.md) §3.1：

| # | 情形 | 处理 |
|---|---|---|
| 1 | 环境**具备** Team 能力 | **必须先询问用户是否使用 Team**，不得自行决定。用户要求用 → 用 Team；用户不要或未表态 → 默认子代理 |
| 2 | 环境**不具备** Team 能力，用户也没提 | 用默认子代理，无需询问 |
| 3 | 用户**显式要求 Team** 但环境不具备该能力 | **回退到默认子代理**，并**显式告知**"当前环境无 Team 能力，已回退" |

**方式不改变标准：** Team 只改变**执行方式**（持久化、可跨轮次协作、可并行写），
**角色定义、派遣矩阵、输出骨架、评分维度、交叉质询与中位数规则完全一致**。
不得因为用了 Team 就放宽或加码审查要求。

**两条禁令：** ① **不得静默降级**；② **不得假装使用了 Team**。

> **S-Nov 按需派遣（○）：** 当 S-Lit 判定为"边缘"，或存在"首次提出"声称时，在
> **Mode B（B5）/ Mode C / Mode E** 中追加 S-Nov 做独立新颖性核验（避免与 S-Lit
> 同源偏差）。
>
> **S-Theory 在 B5 按需（○）：** 仅当该 idea 含理论声称时才派；在 Mode C 的 C2 属
> 常规派遣（●）。
>
> **S-Repro 只在 Mode E 常规出现**（在 Mode D 的叙事审核中按需）。Mode B 的审核对象
> 是一句话级 idea，没有代码可复现；把 S-Repro 派到 B 属于职责错配。
>
> **三种审查深度不同，不要混用：**
> - **B5** 概念级快筛：双评分 + 一条致命反驳，不要求交叉质询、不要求每人 200 字；
> - **D 的叙事审核**：6 个维度化子代理（**6 个全部派遣，不得裁减；S-Lit 恒派**，
>   见 [mode-d](mode-d-narrative-generation.md) §D3）+ 交叉质询 + **逐维度中位数**
>   （见 [mode-d](mode-d-narrative-generation.md) §D4）；
> - **E2** 方案级深审：八子代理 + 交叉质询 + 中位数评分。
>
> 详见 [mode-b](mode-b-idea-discovery.md) §B5 与 [mode-e](mode-e-proposal-review.md) §E2。

> **锚定点（核心目标）决定各角色「最该盯什么」**（见 [../SKILL.md](../SKILL.md) §0.1）：
> - 主锚点 = **理论** → S-Theory 与 R-ICML 的**证明正确性**是首要审查项；
> - 主锚点 = **性能** → A-Experimenter 与 R-CVPR 的**公平比较与指标口径**是首要审查项；
> - 主锚点 = **现象 / 基准** → R-NeurIPS 的**洞察深度与解释唯一性**是首要审查项；
> - 主锚点 = **可行性 / 负结果** → S-Feas 与 S-Theory 的**假设现实性**是首要审查项。
>
> **角色本身不增不减**——锚点改变的是审查侧重，**不是派遣名单**。

## 5. 子代理输出的统一骨架

```markdown
## <角色名> 评审

### 理论角度
<命题 / 假设 / 推导是否成立；形式化缺口在哪。偏应用的工作也要说清理论侧是否成立>

### 应用角度
<能否落地；可验证性；影响面；与真实工作流的兼容性。偏理论的工作也要说清应用可达性>

### 会议特性判定
<按本会议首要标准给出一条判定，必须引用 venue-standards.md 的具体条目>

**结论：** <一句话判定>
**评分：** <1—5 分，Mode D / Mode E 需要>

### 依据
- [作者, 会议/年份] ……

### 质疑 / 补充（Mode D / Mode E 交叉质询必填）
- 对 <角色名> 的评分：……（至少一条）

### 待核实
- ……
```

> **三段（理论角度 / 应用角度 / 会议特性判定）缺一即为不合格评审**（见 §1.0）。
> 该骨架适用于**所有审稿人视角角色**（R-CVPR / R-ICML / R-NeurIPS / R-MICCAI）；
> 审查类角色（S-*）按各自职责输出，不强制三段。

## 6. Mode D 叙事审核专用量表

Mode D 对**每一套叙事**派遣下列 6 个子代理，**6 个全部派遣、不得裁减；S-Lit 恒派**
（叙事的新颖性声称未必写成"首次提出"，仍需文献核实；见
[mode-d](mode-d-narrative-generation.md) §D3）。

**每个会议审稿人（R-CVPR / R-ICML / R-NeurIPS / R-MICCAI）都要给出「两角度 + 会议特性」**
（§1.0）：两张通用角度分 + 两张本会议特性分。

| 子代理 | 通用角度（1—5） | 会议特性维度（1—5） | 极性 | 附加输出 |
|---|---|---|---|---|
| **R-CVPR** | 理论角度、应用角度 | 方法贡献、可验证性 | 高 = 好 | — |
| **R-ICML** | 理论角度、应用角度 | 原创性、理论严谨性 | 高 = 好 | — |
| **R-NeurIPS** | 理论角度、应用角度 | 洞察深度、重要性 | 高 = 好 | **贡献类型判定** |
| **R-MICCAI** | 理论角度、应用角度 | 临床相关性、验证严谨性（**条件性**） | 高 = 好 | **数据许可 / 伦理审批 / 按受试者分组划分 / 统计检验**的核对结论 |
| **S-Devil** | — | 新颖性反驳（**5 = 完全无新颖性**） | **低 = 好（反向）** | **致命弱点 ≥3 条** + 最接近先前工作 |
| **S-Lit** | — | —（给出核实结论） | 类别值 | 最接近先前工作 **≥5 篇** + 核实结论（确认新颖 / 部分重叠 / 已被覆盖） |

> **意见字数下限见 §7 总表**（Mode D 子代理 ≥200 字，**S-Devil ≥250 字**）。

**维度向量如何组成（强制）：**

1. **通用角度（理论角度、应用角度）：** 四个会议审稿人**各自打分**，**先跨审稿人取
   中位数**，各得 **1 个值**进入向量 —— 这样"两角度"不会因为打了 4 次而被放大 4 倍。
2. **会议特性维度：** 各审稿人自己的两个维度，直接进入向量（这是"突出会议特性"的量化部分）。
3. **R-MICCAI 的条件性维度：** 工作无临床 / 医学影像属性时记 `N/A`，**不进向量**。
4. **S-Devil 的反向维度：** 归一化为 **新颖性稳健度 = 6 − 反驳分** 后进入向量。
5. **不进向量：** 致命弱点条数、S-Lit 核实结论（作门禁 / 上下文）。

因此向量 = **2 个通用角度 + 8 个会议特性维度 + 1 个新颖性稳健度 = 11 个**
（R-MICCAI 不适用时 **9 个**）。

**综合评分规则（强制）：** 必须覆盖**全部维度**，**聚合前必须先做极性归一化**；
随后**逐维度取中位数**；**任一归一化维度中位数 ≤ 2 则不得推荐为最佳**（即使创新性很高）。

> ⚠️ **不要漏掉归一化**：直接聚合会把"最 novel"（反驳分低）否决、把"无新颖性"
> （反驳分 5）当高分。详见 [mode-d](mode-d-narrative-generation.md) §D4.1 与
> [scoring-policy.md](scoring-policy.md)。
