# 证据等级与措辞政策（所有 Mode 共用）

本流水线**只有一个**「证据等级 ↔ 允许/禁止表述」的权威定义，就是本文件。
**所有 Mode 一律引用本文件，不再各自定义措辞**——各自重复写一遍定义就是新的漂移源。

## 1. 五级证据等级

| 等级 | 含义 | 允许表述 | 禁止表述 |
|---|---|---|---|
| **已核实** | S-Lit / 实验确认 | 「已核实」「据 X 证实」 | — |
| **部分核实** | 部分维度确认 | 「部分核实（哪一维度未核实）」 | 「已核实」 |
| **据本次检索未见** | 完成 **L2** 及以上检索，且附**负检索记录** | 「据本次检索未见（检索式见附录）」 | 「没人做过」「首次」「首次提出」 |
| **待核实** | 未达 L2（L1 或未检索）或信息不足 | 「待核实」 | 任何确定性声称 |
| **待补证明** | 证明预算用尽（见 [../SKILL.md](../SKILL.md) §1.5） | 「待补证明 · 待核实」 | 「已证明」 |

## 2. 使用规则（强制）

1. **先定等级，再选措辞。** 不确定属于哪一级时，按**更保守**的一级写。
2. **「首次提出」类声称的三项门禁**（另见 [../SKILL.md](../SKILL.md) §1.2）：
   ① 完成 T1 的 **L3 穷尽检索**、② 经 **S-Lit 核实**（必要时 S-Nov 独立复核）、
   ③ 附**负检索记录**。三项缺一，只能降级为「据本次检索未见」（该措辞本身要求
   **L2 + 负检索记录**，见 §1）；**若连 L2 都未达到，只能写「待核实」**。
3. **负检索记录**是「据本次检索未见」这一措辞的**唯一依据**：检索式列表 + 每式命中数
   + 为什么这些命中不足以否定该声明。
4. **未达到 L2、或未附负检索记录**时，新颖性结论只能写「待核实」，且**不得**给出
   「复现风险低」。**未完成 L3** 时，额外**不得**使用「首次提出」类声称（见 §2 规则 2）。
5. **禁止推断**（与 [literature-policy.md](literature-policy.md) §4 一致）：
   本地未命中 ≠ 不存在；arxiv 未见 ≠ 无人研究过；429 中断 ≠ 检索完整。
6. **未核实条目不支撑创新性声明**：`needs_verification = true` 的文献条目、
   「待核实」的无人区声称，都不得用于支撑"首次提出"或任何确定性结论。
7. **`needs_verification` 有明确后果，不只是个标记**（与 `docs/refs/index.json` 闭环）：
   - `needs_verification = true` 的条目**不得**用于支撑「首次提出 / 未见前作 / 复现风险低」
     类声明 —— 它的元数据来自文件名兜底，标题、作者、年份本身就可能错；
   - **其数量必须计入根 `INDEX.md` 的全局 Warnings**（见
     [project-layout.md](project-layout.md) §4.4）；
   - 数量**超过 5** 时触发**补元数据的 TODO**（为对应 PDF 写 sidecar
     `docs/refs/papers/<paper_id>.json`，再重建索引），**不得**让它长期累积。
8. **禁止臆造引用**；无法确认处一律标「待核实」。

## 3. 认知状态 ↔ 措辞等级映射

[claim-first-policy.md](claim-first-policy.md) §2 的证据台账给每条证据标 `epistemic_status`
（五个枚举值，逐字取自仓库级 spec `docs/claim-first-spec.md` §2.1，该文件不进安装副本）。
**本节只做映射，不新立等级** —— 措辞等级仍只有 §1 的五级，判定权仍在 §1。

| `epistemic_status` | 含义 | 对应 §1 措辞等级 | 附加约束 |
|---|---|---|---|
| `Observed` | 已观察到的实验 / 数据事实 | **已核实**（实验 / 数据确认） | 可写「据本次实验」；必须能指到具体实验 / 数据位置 |
| `Supported` | 有文献或既有理论支持 | 默认 **部分核实**；满足 §1 的「已核实」条件（**L3 + S-Lit 核实**）后才可写 **已核实**；声称「未见前作」且附负检索记录时可写 **据本次检索未见**；未达 L2 → **待核实** | **不得**仅凭 `Supported` 直接写「已核实」 |
| `Hypothesized` | 假设，未验证 | **待核实**（台账另标 `[待验证]`） | 不得任何确定性声称 |
| `Planned` | 计划中、尚未产生的证据 | **待核实**（台账另标 `[待补]`） | **不得当作证据引用**；不得进 `S5 Evidence Contract`；只出现在 D9 的缺失证据清单与最小必要实验 / 定理里 |
| `Unknown` | 未知 | **待核实**（台账另标 `[待补]`） | 不得当作证据引用 |
| 任一条目（含 `Observed` / `Supported`）且为定理 / 命题类、证明预算已用尽 | —（认知状态不覆盖此情形，见下） | **待补证明 · 待核实** | 不得写「已证明」，也不得因它与 §1 的「已核实」冲突而降级或升级 |

**硬规则：**

1. **只有 `Observed` / `Supported` 可支撑确定性表述**，且 `Supported` 的确定度按上表分级
   降档；`Hypothesized` / `Planned` / `Unknown` 一律按「待核实」写。
2. **`Planned` / `Unknown` 不得进入 Evidence Contract（`S5`）**：对应 claim 写成
   `Ci ← [待补]`，并进 D9 的「缺失证据清单」与「最小必要实验 / 定理」。
3. 映射只改**措辞等级的选择**，不改 §1 的允许 / 禁止表述，也不改 §2 的使用规则。

**与「待补证明」的关系：** 「待补证明」不是认知状态，而是**证明预算用尽**的处置
（见 §1 与 [../SKILL.md](../SKILL.md) §1.5）。任一条目（含 `Observed` / `Supported`）
若属定理 / 命题类且证明预算用尽，措辞只能是 **「待补证明 · 待核实」**，不得写「已证明」。

> **模式下调用：** R2 / R5 的检索结论、R3—R6 的 idea 新颖性判定、R8 的创新性
> 判定、R12 的叙事新颖性声称与证据台账 `epistemic_status`、R7 / R10 / R13 的防复现结论，
> **都引用本文件**，不另立措辞表。台账的字段定义见
> [claim-first-policy.md](claim-first-policy.md) §2，映射见本节。
