# 顶会论文叙事套路库（Mode D 锚定用）

> **记法警告：** 本文档与 [mode-d](mode-d-narrative-generation.md) 中的
> **「A 领域 / B 理论」是领域占位符**（A = 要解决问题的目标领域，B = 提供理论工具的
> 来源领域），**与 Mode 字母 A/B/C/D/E 无关**。
> 而 `N1—N10` 是**套路编号**，也不是 Mode。

叙事重心必须从 **"我们引入了 B"** 转移到 **"A 领域存在结构性缺口，B 恰好补上该缺口"**。
只停在"A 有问题，用 B 解决"的叙事，在顶会评审中大概率被判**增量应用**。

---

## 1. 十套叙事逻辑

对每个 idea，从中选择**至少 4 套**尝试。选择依据是 idea 的**贡献类型与结构特征**。

| # | 叙事逻辑 | 核心句式 | 适合会议 | 主要风险 |
|---|---|---|---|---|
| N1 | **新问题/新设定** | 我们发现一个被忽视的问题或设定，并形式化它 | NeurIPS、CVPR | 问题不够重要 |
| N2 | **瓶颈突破/移除假设** | 现有方法依赖假设 X，在 Y 下失效；我们移除 X | ICML、NeurIPS | 假设移除不彻底 |
| N3 | **跨域理论迁移** | A 缺少理论工具，我们从 B 引入并证明迁移条件 | ICML | 被视为简单应用 |
| N4 | **现象发现与解释** | 我们观察到反直觉现象，分析原因并据此设计方法 | NeurIPS、ICML | 解释不唯一 |
| N5 | **统一框架** | 现有方法都是我们框架的特例，我们导出新算法 | ICML、NeurIPS | 只有框架没有新算法 |
| N6 | **效率/可行性** | 现有方法太贵，我们使其可行且保持理论保证 | CVPR、ICML | 被归为纯工程 |
| N7 | **鲁棒性/泛化** | 现有方法在分布偏移/非平稳下崩溃，我们解决 | NeurIPS、ICML | 设定不够新 |
| N8 | **Benchmark/评测** | 现有评测掩盖关键失败，我们建立新基准并给出方法 | CVPR、NeurIPS | 贡献被归为数据集 |
| N9 | **矛盾解决** | 先前结果矛盾，我们找到原因并统一解释 | ICML、NeurIPS | 原因不够关键 |
| N10 | **不可能性/负结果** | 我们证明在 Y 下不可能做到 X，并给出可达到的松弛 | NeurIPS | Theory 范围太窄 |

### 1.1 选择规则

| idea 的贡献类型 | 优先套路 |
|---|---|
| 方法（新架构/新算法） | N2、N5、N6、N7 |
| 理论（定理/界/不可能性） | N3、N5、N10、N2 |
| 实证（现象/评测） | N4、N8、N9、N1 |
| 问题定义 | N1、N9、N8 |
| **跨领域理论 B 引入任务 A** | **N2、N3、N5、N9（强制四套）** |
| Concept & Feasibility | N1、N6、N8 |

> **跨域类 idea 的硬性要求：** 只要涉及"把理论 B 引入任务 A"，**必须**尝试
> N2 / N3 / N5 / N9 四套，并**严格按 §2 的五步升级**撰写每一套。

## 2. 跨领域叙事的五步升级（强制）

跨域叙事**不得**停留在"A 有问题，B 能解决"。必须完成以下五步：

| 步 | 内容 | 审稿人对应问题 |
|---|---|---|
| 1 | **结构性缺陷**：A 领域现有方法**共享假设 X**，导致在条件 Y 下**结构性失效**。失败原因必须具体到**机制层面**，不能是"效果不好"。 | 为什么 A 内部做不到？ |
| 2 | **结构同构**：A 中的结构性质与 B 中的定理/机制具有**同构关系**，而非表面相似。必须指明对应的是什么数学结构。 | B 为什么结构上适配？ |
| 3 | **迁移合法性**：证明 B 的假设在 A 中**如何修改**，给出**迁移合法性定理**。**这是最容易被审稿人攻击的环节。** | B 的迁移是否合法？ |
| 4 | **新算法**：基于该定理**设计**新算法，而不是直接套用 B。 | 是否有方法层面的增量？ |
| 5 | **实证**：实验证明新算法优于 A 领域**最强基线**，且**消融证明 B 带来的结构是必要的**。 | 结构必要性是否被验证？ |

> 五步缺一，该套叙事**不得**标为"可用于投稿"；应在输出中标注缺口位置。

---

## 3. 禁用表述（无信息量）

叙事与贡献清单中**禁止**出现：

- ❌ "显著提升"、"有效解决"、"性能优异"（除非紧跟具体数字与口径）
- ❌ "泛化性不足"、"缺乏理论分析"、"效果不够好"（必须指向具体结构性质或理论条件）
- ❌ "我们首次提出"（未标注"待文献核实"前）

**替换要求：** 每一处评价必须给出**具体机制、具体条件、具体数字**三者之一。

---

## 4. 叙事包装：重新定位，不是夸大

**叙事包装 = 在不改变任何事实的前提下，改变读者理解该工作的参照系。**

| 允许（重新定位） | 禁止（夸大） |
|---|---|
| 把"提出新模块"定位为"移除假设 X" | 编造未做的实验 / 未证明的定理 / 未测的数字 |
| 把"数据集上更好"定位为"现有方法在条件 Y 下结构性失效" | 把"3 个数据集有效"写成"普遍有效" |
| 把"组合 A 与 B"定位为"建立同构关系 + 迁移定理" | 把"部分重叠"写成"首次提出" |
| 改变贡献类型归类（方法 → 理论 / 问题定义） | 用"显著提升"替代具体数字与口径 |
| 把"改进 X"定位为"统一 X/Y/Z" | 承诺方案里没做的事 |

**唯一判定标准：** 包装后的每一句声称，都必须能在**方案（Mode C 的 proposal /
实验计划）**中找到对应证据。找不到 → 删除或标注"待补充"。

**每套叙事必须附「包装前后对照」小节**，写明改了哪个参照系、依据哪条证据。

## 5. 叙事自检清单

每套叙事产出后逐条核对：

- [ ] 叙事重心是"结构性缺口被补上"，而不是"我们引入了 B"。
- [ ] 第二段（困境）的失败原因具体到**机制层面**。
- [ ] 第三段（桥接）说明的是**结构同构**，不是"两个领域都在做类似的事"。
- [ ] 跨域类已完成**五步升级**，尤其第 3 步给出了**迁移合法性定理**。
- [ ] 贡献清单 3—4 项，每项**标注贡献类型**。
- [ ] 回答了**"为什么之前没人做"**（至少一个具体理由）。
- [ ] 诚实写出该套路的**弱点**（1—2 条）。
- [ ] 无 §3 的禁用表述。
- [ ] 所有引用为 `[作者, 会议/年份]`。
- [ ] "首次提出"已标 **"待文献核实"**（S-Lit 核实后方可保留）。
