# Mode C — proposal-generation（方案生成）

基于 idea 做创新性与可行性研究，产出论文提案 + 实验流程。

## 输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 一个或多个 idea | ✅ | 来自 Mode B 的 `idea_candidates`，或用户直接提供 |
| 关键参考文献 | ❌ | 种子文献；缺省时调用 Mode A |
| 资源约束 | ❌ | 算力 / 数据 / 人力 / 时间 / 开源要求 |

**信息完整性检查（开工前）：** idea 是否足够具体到可设计实验？若只是方向词
（如"扩散模型 + 组合优化"），先要求用户收敛，或从 Mode B 的候选清单中选一条。

> **锚定点（核心目标）必须先确认**（见 [../SKILL.md](../SKILL.md) §0.1）。
> 本 Mode 受锚点约束：**贡献类型必须与主锚点一致**；C4 的实验计划按锚点加严要求——
> **理论**锚点必须有证明 / 反例 / 边界条件，**性能**锚点必须有同算力·同数据·同调参的
> 公平比较与显著性检验，**基准**锚点必须有新基准的构造与失败模式分析。
> 锚点与方案不一致时（如性能锚点却没有公平比较），**必须显式指出**。

---

## C1. 创新性研究

**派遣：** R-CVPR / R-ICML / R-NeurIPS / R-MICCAI 四视角**分别独立**评估该 idea 的创新性；
同时派遣 **S-Lit** 核实最接近的先前工作。

- 四视角必须引用 [venue-standards.md](venue-standards.md) 中的**具体标准条目**。
- **四个审稿人一律按「两角度 + 会议特性」评审**（见
  [roles.md](roles.md) §1.0、[venue-standards.md](venue-standards.md) §0）：
  先给**理论角度**与**应用角度**的实质判断，再给**本会议特性判定**。
  只写一个角度、或不给会议特性判定，视为评审不合格。
- **R-MICCAI 的适用性：** 工作无临床 / 医学影像属性时，仍以通用视角参与理论 / 应用
  两角度评价，会议特性判定写 **"不适用"** 并说明理由，不得硬凑临床相关性。
- S-Lit 输出：最接近的 3—5 篇 + 重叠维度 + **重叠度判定（足够 / 边缘 / 不足）**。
- 若 S-Lit 判定为"边缘"，**追加 S-Nov** 做独立新颖性核验。

**C1 是「增量复核」，不是把 B5 重做一遍：**

- 只对 B5（[mode-b](mode-b-idea-discovery.md) §B5）判为 **「边缘 / 不足」** 的项做深化；
- B5 已判 **「足够」且期间无新文献**的项，**不重做 L3** —— 直接引用 B5 结论并**标注
  来源**（`A002/I3` 的 B5 审核结论 + 检索等级）；
- 若**期间出现新文献**，则**必须重做**相应检索；
- 无论是否重做，创新性结论的措辞等级一律见
  [evidence-policy.md](evidence-policy.md)。

**输出：**

1. **创新性判定** —— 使用 [venue-standards.md](venue-standards.md) §6 的模板。
2. **创新性边界重界定** —— 相对 Mode B 的边界，本次核实后更新三区划分，
   所有"无人区"声称标注 `已核实` 或 `待核实`。

## C2. 可行性研究

**派遣：** S-Feas（工程可行性）+ S-Theory（理论基础与假设合理性）。

| 子代理 | 输出 |
|---|---|
| S-Feas | **可行性评分（1—5）** + 资源估算（算力/数据/人力/时间）+ 瓶颈清单 + 缓解方案 + 顶会匹配度 |
| S-Theory | 理论基础是否成立、隐含假设、边界条件、反例或紧性讨论 |

**输出：**

- **可行性评分**（含评分理由）
- **风险清单** —— 每行：风险 / 类型（工程/理论/数据/时间）/ 概率 / 影响 / 缓解方案 / 残余风险
- **缓解方案** —— 必须有可执行的下一步，不是"多加实验"

## C3. 论文格式展开（由 **A-Author** 执笔）

按以下结构输出提案，**必须逐节作答，不得跳过**：

| # | 章节 | 要求 |
|---|---|---|
| 1 | **背景** | 问题是什么、为什么重要、当前状态 |
| 2 | **核心贡献** | **3—4 项**，每项标注**贡献类型**与**方法来源**（`原创` / `部分原创` / `迁移`，判据见 [venue-standards.md](venue-standards.md) §5.1） |
| 3 | **相关工作** | 含**精确差异**，每条引用 `[作者, 会议/年份]` |
| 4 | **动机** | **必须回答"为什么之前没人这么做"** |
| 5 | **实验设计** | 含**失败条件** |
| 6 | **可能的结论** | 预期结论 + 替代解释 |

### C3 · 第 4 节「动机」的特别要求

这是本 Mode 最容易被跳过、也最影响审稿的一节。必须给出**至少一条**具体原因，
并说明为什么该原因现在不成立了：

- 技术原因（此前缺少某工具/表示/硬件）
- 数据原因（此前无某数据集/标注）
- 理论原因（此前缺少某性质刻画，导致方法无从设计）
- 社区原因（此前该问题被归入另一领域，视角不同）

> ❌ "因为没人想到" —— 不接受。
> ❌ "因为我们首次提出" —— 循环论证，不接受。

## C4. 实验流程设计（由 **A-Experimenter** 执笔）

按以下 **14 节（0—13）** 结构输出。逐节作答，缺节即视为交付不完整。

| # | 章节 | 关键要求 |
|---|---|---|
| 0 | **信息完整性检查** | 数据/算力/基线是否可得；缺失项标注"待核实" |
| 1 | **贡献—实验映射表** | 每条贡献 → 对应实验，**不得有贡献无实验、无实验对应无贡献** |
| 2 | **实验假设与变量设计** | 含**证伪条件**；自变量 / 因变量 / 控制变量 |
| 3 | **数据与基准** | 数据集、划分、预处理、规模 |
| 4 | **基线与公平比较** | 基线选取理由；**同算力/同数据/同调参预算** |
| 5 | **评估指标与统计方案** | 主指标 + 次指标；随机种子数、误差棒、显著性检验 |
| 6 | **实验阶段与流程** | **实验卡片**（编号/目的/输入/输出/耗时）+ **审稿人质疑与回应** |
| 7 | **消融矩阵** | 每个关键设计一个消融；标注优先级 |
| 8 | **鲁棒性、泛化与公平性** | 分布偏移、超参敏感性、子群表现 |
| 9 | **效率与资源预算** | 训练/推理成本、显存、GPU·小时 |
| 10 | **可复现性清单** | 代码/数据/超参/种子/环境/算力披露 |
| 11 | **预期结果与失败条件** | 明确的失败条件（什么结果意味着假设不成立） |
| 12 | **实验优先级与依赖关系** | 依赖图；先做哪些、哪些可砍 |
| 13 | **论文呈现计划** | 每个实验 → 哪张图表、放正文还是附录 |

**实验卡片模板：**

```markdown
#### E<n>：<实验名>
- **目的：** 验证 <贡献 K<n> / 假设 H<n>>
- **输入：** 数据 …；模型 …
- **变量：** 自变量 …；控制变量 …
- **输出：** 指标 …
- **证伪条件：** 若 … 则假设不成立
- **预算：** <GPU·小时>
- **依赖：** E<m>
- **审稿人质疑：** … → **回应：** …
```

## C5. 输出

| 交付物 | 规格 |
|---|---|
| **论文提案** | 字数下限见 [roles.md](roles.md) §7 **字数与规模下限总表**（1500—2000 字） |
| **实验流程计划书** | 覆盖 C4 全部 14 节（0—13） |
| **创新性判定** | 四视角 + S-Lit 核实结论 |
| **可行性评分** | 1—5 + 理由 |
| **风险清单** | 含缓解方案与残余风险 |

## C6. 文档落盘与 INDEX 更新（强制）

1. **写文档（两份，各占独立序号）：**
   - 方案：`<routeX>/docs/<R>NNN-proposal.md`
   - 实验计划：`<routeX>/docs/<R>NNN-experiment-plan.md`（取下一个可用序号）
   每份文档都按 project-layout.md §2.6 扫描现有最大序号 +1，**序号永不复用**。
2. **frontmatter：** `mode: C / type: proposal | experiment-plan / status / created`。
3. **更新该路线 `INDEX.md`：**
   - §2 文档索引：新增两行；
   - §3 已证实：C1/S-Lit 已核实的结论；
   - §4 已证伪：被 S-Lit/S-Theory 否定的假设；
   - §5 TODO：实验优先级与依赖 → 转成 TODO 条目，标注 P0/P1 与依赖；
   - §6 Bugs：已知的工程障碍（如基线跑不通）；
   - §7 Warnings：**未缓解的风险、未完成 L3 的"首次提出"声称**；
   - §8 关键依赖与风险：数据/算力/外部依赖；
   - §9 变更日志。
4. **创新性声明的门禁：** 若 C1 要用"首次提出"，必须已完成 T1 的 **L3 穷尽检索**
   并附负检索记录；否则降级为"据本次检索未见"，或记入 Warnings。
