# Research Idea Pipeline v1.0.0 — First Stable Release

**Release date:** 2026-10-10 · **Component:** `research-idea-pipeline/` · **Tag:** `research-idea-pipeline/v1.0.0`
**Baseline:** `origin/main` @ `7c36fae` (Loop Runtime Correctness Hotfix + R7 Assurance merged)

---

## 1. Overview

Research Idea Pipeline 是一个面向机器学习与科学研究、以**可持久化 Research State** 为中心的
科研搜索与证据驱动决策系统。它把"该研究什么、这个结果说明了什么、下一步做什么"变成可检查的
状态迁移：每一条结论都要落到八类 canonical 对象上，每一次执行都要有预注册与证据资格，每一次
状态变化都要有可追溯的事务凭证。

它是一个**科学探索与检验系统**，不是自动生成论文文字的流水线：系统负责扩大候选、构造可区分
预测、攻击自己的解释、在证据不足时拒绝升级结论；它不负责把不确定的结果写成确定的故事。

v1.0.0 是第一个正式稳定版。**版本序列从此重新建立**：此前的 v1.2.0—v2.3.3 是同一组件的公开
开发迭代记录（见 [CHANGELOG.md](../../CHANGELOG.md)），没有被删除或改写。

## 2. Architecture

```
用户意图（四个语义入口）
  start-project · continue-research · explore · audit
        │
        ▼
Intent Router（`preset_router.py`，16 个 Preset）───► 当前选中的**一个**协议
        │
        ▼
R0—R14 双循环
  Discovery（R3—R6：扩大候选、保持多样性、范式逃逸）
  Assurance（R7/R10/R13：攻击、修复、完整性门禁）
        │
        ├── canonical Research State（八类对象：claims / evidence / assumptions / hypotheses /
        │     experiments / literature / failures / uncertainties）
        ├── Scheduler（`scheduler.json`，出 state 的遥测：优先级、EIG 校准、算子统计）
        ├── Execution Gate（PEIG/AALG：风险对照、有限诊断、内容绑定 receipt）
        └── Cognition（`cognition/`：机制 / 异常 / 竞争记忆 + append-only 修订日志 + 回放）
```

**权威边界（不可越权）**

| 层 | 是否科学权威 | 说明 |
|---|---|---|
| `research-state.json` | **是，唯一** | 冻结预注册、原始实验产物是科学事实依据 |
| `cognition/`、`scheduler.json`、`assurance/outcome/` | 否 | 索引、派生投影、遥测、程序性审查；可由 state 与修订日志重建或复核 |
| Preset / Router / Loop | 否 | 只做路由与排练；不得改证据标准、锚点或授权 |

## 3. Discovery & Scientific Insight

- **多路径发现（R3—R6）**：候选必须带结构签名（假设距离 / 表述距离 / 表示距离 / 理论透镜距离 /
  机制距离），多样性由结构与 niche 保证，而不是靠提示词鼓励。
- **探索算子（P1—P6）与探索下限**：算子降级需要 ≥2 次独立失败、限定问题结构，并保留重启条件；
  不得永久封禁算子或岛屿。
- **结构等价与 QD**：新候选必须通过结构等价审计，避免"换名字的同一个想法"。
- **机制假说与竞争解释**：机制竞争要求各机制拥有**不同的冻结判据**，否则竞争不可判定。
- **可区分预测与判别干预**：预测冻结在 `preregistration.outcomes[]`，事后声明 `observed_outcome`
  一律按完整模式判定；干预以"能改变哪个决定"排序，而不是"最容易涨指标"。
- **Paradigm Escape**：以 canonical 对象为准做五轴表示重建（对象 / 变量 / 假设 / 目标 / 约束），
  输出必须标注 `requires_structural_audit` 与"参数替换不算范式改变"。

> **不声称**：系统尚未在真实科研 A/B 中被证明具有超越其他科研 Agent 的创新能力（见 §9、§10）。

## 4. Cognitive Insight Engine

| 记忆 | 内容 | 可由什么重建 |
|---|---|---|
| Mechanism Memory | 机制模型、支持等级（由 canonical 证据推出，不接受自评） | `research-state.json` + 修订日志 |
| Anomaly Memory | 未解释观察、异常与冲突 | 同上 |
| Competing Explanations | 未完成竞争、各自冻结判据 | 同上 |
| Scientific Value | 分维的 Decision Value / Discovery Potential（**无加权总分**） | 同上 |
| Strategy Memory | 算子先验、结构化范围、重启条件、策略决策遥测 | 同上 |
| Revision / Replay | append-only 修订日志；Discovery Replay 以隐藏答案评分（七维、无加权总分） | 日志本身 |

**已经程序验证的**：投影可由 canonical + 日志逐字节重建；支持等级只来自证据等级；跨会话恢复
机制模型、失败约束与未完成竞争；修订写入者权限与校验者一致（`SV6`/`CM1`）；策略建议只能在同一
`EIG ÷ cost` 层内、且只在已过硬门禁的动作之间重排，并把采纳与否与原因写入 `scheduler.strategy_decisions[]`。
**仍需真实科研验证的**：这些记忆是否真的让研究**结果**更好（L3，见 §9）。

## 5. Autonomous Research Loop

- **四个语义入口**：`start-project`（首次接管，只观察不推进）/ `continue-research` / `explore` / `audit`。
- **16 个 Preset**：6 个主动（科研闭环 / 范式逃逸 / 状态恢复 / 科学重规划 / 对抗审查 / 进展回顾）、
  7 个 Loop 自动恢复（证据冲突 / 上下文漂移 / 记忆整合 / 资源 / 工程失败 / 体检 / 停滞打破）、
  3 个自进化（策略进化 / 假设再平衡 / 回放评估）。
- **Intent Router**：中文 / 英文 / 别名 / 显式 id 均可解析；否定按**分句**判定；歧义取**最小授权**；
  只陈述问题先只读诊断；只读提问绝不升级为执行；每次只加载共同契约 + **一份**协议。
  `preset_router.py check --fixtures` 覆盖 53 条基准（48 正例 + 5 约束/否定反例）。
- **Event Trigger 与 Runtime 职责边界**：本 skill 提供可执行、幂等、带冷却与上限的触发/记录接口
  （`trigger` / `record` / `cognition/recovery-log.jsonl`），**不安装后台守护进程、不声称无人值守
  自动执行**；事件监听与持续派遣由调用方（既有 Scheduler / 宿主 Runtime / Hook）负责。
  用户主动预设即使被 registry 标为事件可触发，也只在显式授权
  （`preset_router.py authorize --scope discovery_only|strategy|full`）后才允许自动触发受控 Discovery，
  且该授权**不覆盖 execute**（不自动启动 GPU、不改主锚点、不绕证据门禁）。
- **Context Recovery**：从磁盘重读契约、canonical state、认知投影与在途任务，绝不重新 Bootstrap。
- **Stagnation Detection**：由 EIG 校准的零增益连击、诊断切换与候选集中度判定，而不是"感觉没进展"。
- **Strategy Decision Adapter**：唯一一条让策略建议进入**真实动作选择**的通道（同层重排 + 遥测记录）。
- **Stop / HOLD 条件**：凭证损坏（`outcome_receipt_blocked`）、审核未通过（`assurance_failed`）、
  审核未决（`assurance_unknown`，等待新信息而不重复送审）、依赖未审核结果（`assurance_pending_dependency`）、
  无合法动作（`no_legal_action`）、权限或预算不足。

## 6. Scientific Integrity

- **Evidence Qualification（`PQ1`—`PQ8`，唯一入口）**：观测包 schema / 缺字段 / 类型 / 越界
  `observed_outcome` / 来源 / 摘要一律 fail closed；判定集合不完整、分支不可追溯、时间顺序被破坏
  或冻结登记无法核验同样阻断。不得授权 Claim 升级、机制否证或 Insight 认证。
- **Prediction Freeze**：互斥分支必须由预注册冻结 `outcome_mode` 与 `branch_rule` 才能进入 branch mode；
  所选分支由冻结规则作用于原始观测导出。
- **Experimental Identifiability**：容量 / 干预强度 / 优化条件 / 可识别性 / 公平对照在**执行前**检查
  （`execution_gate.peig`）；执行收据与 manifest/配置/预注册绑定，dry-run 记录永远不能当作执行证据。
- **PEIG / AALG**：风险对照与有限诊断；诊断预算**永不被恢复流程刷新**。
- **Result Provenance**：`run` 在外部命令启动前**原子消费**一次性 receipt；预览（不带 `--execute`）
  零副作用：不写 `consume`、不扣 GPU 小时与 Pilot 次数、不占用收据。
- **R9.O Outcome Analysis**：区分有效负证据与无效执行；工程故障（OOM/NaN/崩溃）不得写成科学否证。
- **R10/R11 状态事务**：完成判定以**正式事务凭证**为准（五键 `outcome_analysis` 通过
  `evidence_outcome.state_errors()`），不要求存在 Repair；Loop 逐实验分类
  `NEEDS_ANALYSIS` / `COMMITTED` / `BLOCKED` / `PENDING_EXECUTION`。
- **R7 T0 Post-update Assurance**：四项检查（integrity / claim_calibration / reproducibility /
  stop_rule_compliance）由 **R7 Agent 本人**完成并给出可追溯理由，经 `assurance-store` 绑定
  `state_digest`/`analysis_digest` 落盘，再由**真实** `decision_gate()` 消费；`FAIL` 阻断、
  `UNKNOWN` 等待、`STALE` 重审、`SUPERSEDED` 跳过。**CLI 不会自动填 PASS**，Loop 也不会自己生成审查。
- **支持边界**：`assurance[].verification_tier` 上限 **T0**；Agent 审查属于程序性审查，
  **不升级 Claim / Evidence / Verification Tier**。
- **工程失败 ≠ 科学失败**：只有通过资格门的结果才能改变科学状态；环境问题只走修复路由。

> **三者不可混淆**：程序验证（哈希、schema、门禁）、T0 Agent 审查、真实科学证据，是三层不同的
> 证据强度。PASS 只释放该实验**已记录的**决策，不启动 GPU、不改锚点、不绕过 R8 预注册与执行门禁。

## 7. Durable Research & Recovery

- **Legacy Handoff**：已初始化项目在 `continue-research` 下只读接管——不重置 state version、claim 状态、
  证据、实验 ID、锚点或诊断预算，不补造历史预测；严重兼容性错误阻止写回（`LH1`—`LH16`）。
- **Context Compaction Recovery**：上下文丢失后由磁盘重建理解，而不是从聊天历史推测。
- **Canonical State**：唯一科学权威；只读预设运行前后逐字节比对，违反即 `PR9` + `BLOCKED`。
- **Cognitive Memory Replay**：投影与修订日志可回放；策略决策可跨会话消费（`state_version` 变化即过期）。
- **Idempotent Runtime Actions**：同一 `(state_version, preset, 信号指纹)` 只触发一次；策略修订按事件
  身份幂等；重复真实执行被拒绝（一次性 receipt）。
- **Failure Memory**：`failures[]` 带 `negative_knowledge` / `stop_rules` / `revisit_conditions`；
  不得为通过测试而批量补造 Repair。
- **Resource Budget**：GPU 小时、Pilot 次数与诊断预算由 ledger 与 policy 约束；历史 ledger
  原样可读（含旧 `dry_run: true` 事件，不再计入预算）。

## 8. Installation & Quick Start

```bash
# 1a) 安装最新 main（分发渠道默认行为；内容随 main 变化）
npx skills add "Zolento/my-research-skills@research-idea-pipeline" -g -y
#    安装副本位于 ~/.agents/skills/research-idea-pipeline（Claude Code / Lingma 为软链）

# 1b) 安装**固定版本** v1.0.0（可复现）：`skills add` 没有 ref/tag 参数，因此先把 Tag 检出到本地，
#     再从该路径安装；实测安装结果与 Tag 树逐字节一致（version: 1.0.0）。
git clone --depth 1 --branch research-idea-pipeline/v1.0.0 \
  https://github.com/Zolento/my-research-skills /tmp/rip-v1.0.0
npx skills add /tmp/rip-v1.0.0/research-idea-pipeline -g -y

# 2) 自检：注册表 ↔ 协议一致 + 意图路由基准
python3 scripts/preset_router.py check --fixtures          # 53/53

# 3) 首次进入已有项目（只观察，不推进）
python3 scripts/legacy_handoff.py detect --state <route>/research-state.json
python3 scripts/legacy_handoff.py audit  --state <route>/research-state.json

# 4) 接管 / 恢复研究上下文（只读）
python3 scripts/preset_router.py resolve --text "恢复之前的科研状态"
python3 scripts/preset_router.py run --preset research-recovery --state <state>

# 5) 跑科研 Loop（先看它准备做什么）
python3 scripts/preset_router.py run --preset research-loop --state <state>
#    需要执行时：execution_gate.py peig → experiment_execute.py run（预览）→ 带 --execute 正式执行

# 6) 范式逃逸 / 对抗审查 / 进展查看
python3 scripts/preset_router.py resolve --text "跳出当前思路"
python3 scripts/preset_router.py run --preset research-audit --state <state>
python3 scripts/preset_router.py run --preset research-review --state <state>

# 7) R7 审查（四项检查，理由必须可追溯）
python3 scripts/evidence_outcome.py assurance-store --state <state> --experiment X-result \
  --reviewer R7 --check integrity=PASS:"audit 摘要与来源已逐项核对" \
  --check claim_calibration=PASS:"C1 由 T2 证据支持，scope 与冻结范围一致" \
  --check reproducibility=PASS:"manifest 配置与预注册一致，对照完整" \
  --check stop_rule_compliance=PASS:"未违反 stop rule"
#    审查步骤与 FAIL/UNKNOWN/STALE 处理见 references/loop-assurance-review.md
```

以上命令在本组件内均已执行验证（见 §9）。`--help` 是参数的权威来源，本文不重复列举会漂移的细节。

## 10. Known Limitations

1. **真实科学发现能力提升尚待 L3 A/B 验证**：现有证据只支持"流程与门禁按规范执行"。
2. **文献来源与近邻判断仍依赖来源完整性**：本地文献库缺失或元数据不全时，近邻/新颖性判断会退化。
3. **Agent 审查（T0）不能等价于高等级科学验证**：它保证程序性与可追溯，不产生 T1+ 证据。
4. **后台运行需要宿主 Runtime 配合**：本 skill 不含守护进程；无人值守的持续派遣由调用方实现。
5. **GPU 与外部操作仍需明确授权和预算**：PEIG/AALG 与一次性 receipt 不可绕过；诊断预算不会被恢复流程刷新。
6. **多 Agent DSH Research Team Bridge 属独立插件项目**，**未**内建于本 skill。
7. 若项目的 `scheduler.json` 不满足调度 schema（缺 `next_actions` / `eig_calibration`），Loop 会
   fail-closed 地不产出 dispatch —— 这是预期行为，需要项目侧补齐遥测。

## 11. From Development History to 1.0.0

本组件此前有多个公开开发迭代版本（v1.2.0 → v2.3.3，共 11 个 tag）。它们**真实存在过**，
本次不删除、不改写、不移动（归档索引与备份见发布准备记录）。

v1.0.0 的作用是**重新建立正式语义化版本序列**：

- 历史 2.x 版本号不再延续（它们记录的是开发过程，而非稳定度承诺）；
- 从 1.0.0 起，版本号表示**对已发布接口与科学门禁的兼容性承诺**：
  patch = 修复且不改变行为契约；minor = 向后兼容的新能力；major = 需要迁移的契约变化；
- `research-idea-pipeline/v1.0.0` 标签指向首次稳定版候选提交，发布说明以本文件为准。
