# Mode D — narrative-generation（多套路论文叙事生成与审稿审核）

**基于 idea 与方案**，建立多种**顶会风格的论文叙事逻辑**，并拉起子代理对这些叙事
进行独立评审与打分；交叉质询后筛出该 idea **最合适的叙事路线**。

> **核心原则：叙事重心必须从"我们引入了 B"转向"A 领域存在结构性缺口，B 恰好补上
> 该缺口"。** 只停在"A 有问题，用 B 解决"的叙事，在顶会评审中大概率被判增量应用。
>
> ⚠️ **记法：** 下文与 [narrative-patterns.md](narrative-patterns.md) 中的
> **「A 领域 / B 理论」是领域占位符**（A = 目标领域，B = 来源领域），
> **不是 Mode 字母**；`N1—N10` 是套路编号，也不是 Mode。

## D0. 定位与边界

**角色：** 你是横跨多领域的**资深论文作者**，熟悉 CVPR / ICML / NeurIPS 的评审逻辑
——即"知道同一份工作在不同叙事下会被如何评判"。本 Mode 由该角色主导叙事生成，
再由 §D3 的审稿子代理独立评审。

**定位一句话：基于 idea + 方案，建立多种顶会风格的叙事逻辑，并拉起子代理评审。**

| 维度 | Mode B（idea） | Mode C（方案） | **Mode D（叙事）** | Mode E（方案审查） |
|---|---|---|---|---|
| 对象 | 想法 | 想法 → 可执行方案 | **idea + 方案的多种「讲法」** | 成型的方案 |
| 核心问题 | 值得做吗 | 怎么做、能不能做成 | **怎么讲才不被判增量** | 做得对不对 |
| 产出 | idea 清单 | 提案 + 实验计划 | **≥4 套顶会风格叙事 + 最佳叙事推荐** | 审查结论卡片 |
| 评审重心 | 方向与概念可行性 | 可行性与创新性 | **叙事结构、结构缺口、迁移合法性** | 方法正确性 + 防复现 |

**一句话：B 决定"做不做"，C 决定"做什么"，D 决定"怎么讲"，E 决定"做得对不对"。**

**D 同时消费 idea 与方案：**

- 从 **idea** 取：核心思路、预期贡献、与现有工作的差异、关键假设。
- 从 **方案（proposal）** 取：贡献清单、相关工作与精确差异、动机、实验设计
  —— 叙事必须与方案的实际做法一致，**不得**在叙事里承诺方案没做的事。

**何时调用：**

- 接 **Mode C** 之后（**推荐**）：idea 与方案都已成型，此时叙事有最充分的素材。
- 接 **Mode B** 之后：只有 idea、暂无方案；可生成叙事，但必须标注
  **"待方案补充"**，且贡献清单只能到"预期"层级。
- **独立**调用：用户直接给出 idea（+ 方案）。

**输出给谁：** 最佳叙事回流到 **Mode C**（按该叙事重写提案）与/或 **Mode E**
（完整审查）。若某 idea 在所有叙事下综合评分均 **< 3**，建议**退回 Mode B**。

## 输入

| 输入 | 必填 | 说明 |
|---|---|---|
| **idea 清单** | ✅ | 每个 idea 的：核心思路、预期贡献、与现有工作的差异、关键假设 |
| **方案（proposal）** | 推荐 | 来自 Mode C 的 `proposal`（含贡献清单 / 相关工作差异 / 动机 / 实验设计）或用户提供。缺失时叙事只能到"预期"层级并标注**待方案补充** |
| 关键参考文献 | ❌ | 3—5 篇最相关论文 |
| 目标会议 | ❌ | CVPR / ICML / NeurIPS |
| 资源约束 | ❌ | 算力、时间、数据、人力 |

### D0.1 信息完整性检查（先做，不得跳过）

**若某个 idea 缺少以下任一项，先输出「待补充信息清单」，并说明哪些叙事无法生成。
不得编造信息。**

| 字段 | 来源 | 缺失后果 |
|---|---|---|
| 核心机制 | idea | 无法生成任何叙事（第四段无法写） |
| 预期贡献 | idea | 无法判定贡献类型 → 无法选套路 |
| 与现有工作的差异 | idea | 无法写第二段「困境」与"为什么之前没人做" |
| 关键假设 | idea | 无法尝试 N2（移除假设）与 N3（迁移合法性） |
| 实验设计 | 方案 | 第五段只能写"预期验证"，须标注**待方案补充** |

## D1. 叙事套路锚定

按 [narrative-patterns.md](narrative-patterns.md) 的十套逻辑，为每个 idea
**选择至少 4 套**。选择依据是 idea 的**贡献类型与结构特征**。

**跨域类硬性要求：** 涉及"把理论 B 引入任务 A"的 idea，**必须**尝试
**N2 瓶颈突破 / N3 跨域理论迁移 / N5 统一框架 / N9 矛盾解决** 四套，并严格执行
[narrative-patterns.md](narrative-patterns.md) §2 的**五步升级**。

## D2. 每套叙事的生成

### D2.1 五段式叙事主线（每套不少于 300 字）

| 段 | 内容 |
|---|---|
| **第一段（问题）** | A 领域面临 [具体任务]，重要性在于 [具体意义]。 |
| **第二段（困境）** | 现有方法在 [什么条件] 下无法 [做到什么]，**根源在于 [什么机制性原因]**。内部修补无法突破，因为 [结构性原因]。 |
| **第三段（桥接/动机）** | 我们观察到 A 中的 [结构性质] 与 B 中的 [结构性质] 具有 [什么关系]。这启发我们 [什么核心思路]。 |
| **第四段（证明/方法）** | 我们证明了 [命题]，建立了 [什么合法性]，并据此设计了 [什么算法]。 |
| **第五段（验证/结论）** | 我们在 [数据集/任务] 上验证了 [什么核心主张]，实验表明 [什么关键结果]。 |

> 第二段的"机制性原因"是整套叙事的承重墙。写不出具体机制，这套叙事不成立。

### D2.2 每套叙事的输出结构

```markdown
#### <idea_id> / <套路编号 Nx> — <套路名称>

**（1）套路名称与适配理由**
该套路为何适合此 idea；与 idea 贡献类型的匹配关系。

**（2）五段式叙事主线**（≥300 字）
第一段（问题）：……
第二段（困境）：……
第三段（桥接/动机）：……
第四段（证明/方法）：……
第五段（验证/结论）：……

**（3）贡献清单**（3—4 项，逐项标注类型）
- [方法] 我们提出 ……，它能够 ……，从而 ……。
- [理论] 我们证明 ……，它能够 ……，从而 ……。
- [实证] 我们展示 ……，它能够 ……，从而 ……。

**（4）为什么之前没人做**
至少一个具体理由：此前缺少技术条件 / 此前被某假设误导 / 此前问题未被定义 /
此前两领域缺乏交流。

**（5）该套路的弱点**
诚实指出最容易被攻击的 1—2 个点。
```

`[类型]` ∈ 方法 / 理论 / 实证 / 问题定义。

### D2.3 汇总格式

| idea | 套路编号 | 套路名称 | 适配理由 | 叙事主线摘要 | 该套路弱点 |
|---|---|---|---|---|---|
| I1 | N2 | 瓶颈突破/移除假设 | … | … | … |
| I1 | N3 | 跨域理论迁移 | … | … | … |
| I1 | N5 | 统一框架 | … | … | … |
| I1 | N9 | 矛盾解决 | … | … | … |

> 上表以**跨域类 idea** 为例，因此填的是强制四套 **N2/N3/N5/N9**。
> 套路编号与名称**必须**取自 [narrative-patterns.md](narrative-patterns.md) §1 的十套表，
> 不得自行改号或改名。

**每个 idea 至少 4 套，每套叙事主线不少于 300 字。**

### D2.4 叙事包装（Packaging）：**重新定位，不是夸大**

**定义：** 叙事包装 = 在**不改变任何事实**的前提下，**改变读者理解该工作的参照系**。

**允许的包装（都是重新定位）：**

| 原始表述 | 重新定位后 | 改变了什么 |
|---|---|---|
| 我们提出了新模块 B | 现有方法依赖假设 X，我们**移除了 X** | 参照系：从"新增能力"→"解除限制" |
| 我们在数据集 A 上更好 | 现有方法在**条件 Y 下结构性失效** | 参照系：从"数值领先"→"失效条件" |
| 我们把 A 和 B 组合起来 | 我们建立了 A 与 B 的**同构关系**并给出**迁移定理** | 参照系：从"工程拼装"→"理论联系" |
| 这是一个方法类工作 | 这是一个**问题定义 / Theory** 类贡献 | 贡献类型归类 |
| 我们复现并改进了 X | 我们**统一了 X、Y、Z**，它们是本框架的特例 | 参照系：从"改进"→"统一" |

**严格执行的禁令（这些是夸大，不是包装）：**

- ❌ 编造未做的实验、未证明的定理、未测量的数字；
- ❌ 把"在 3 个数据集上有效"写成"普遍有效"；
- ❌ 把"部分重叠"写成"首次提出"；
- ❌ 用"显著提升""有效解决"替代具体数字与口径；
- ❌ 承诺**方案（Mode C 的 proposal）里没做**的事。

**判定标准（唯一的、可机械执行的）：**

> **包装后的每一句声称，都必须能在 Mode C 的 proposal / 实验计划里找到对应证据。**
> 找不到对应证据的，就是夸大 —— 必须删除，或标注 **"待补充"**。

**包装必须写在文档里：** 每套叙事附一小节「包装前后对照」，说明改了哪个参照系、
依据哪条证据。这样审稿人（和未来的你）能一眼看出这是定位，而不是造假。

## D3. 审稿子代理派遣与叙事审核

把每套叙事提交给下列子代理**独立审核与打分**。**默认全部 5 个**；idea 数量过多时
可裁减，但**每套叙事至少被 3 个子代理审核**，且只要叙事中出现"首次提出"，
**必须包含 S-Lit**。

| 子代理 | 角色 | 输出 |
|---|---|---|
| **R-CVPR** | CVPR 资深审稿人：方法落地、技术正确性、可复现性，警惕"新颖性谬误" | 方法贡献评分 1—5、可验证性评分 1—5、意见 **≥200 字** |
| **R-ICML** | ICML 资深审稿人：广义原创性、理论深度、限制性假设的移除 | 原创性评分 1—5、理论严谨性评分 1—5、意见 **≥200 字** |
| **R-NeurIPS** | NeurIPS 领域主席：贡献类型区分、洞察深度、Concept & Feasibility 门槛 | 贡献类型判定、洞察深度评分 1—5、重要性评分 1—5、意见 **≥200 字** |
| **S-Devil** | 敌对审查员：**只找最致命弱点，不做平衡评价** | 致命弱点 ≥3 条、最接近先前工作、新颖性反驳评分 1—5（**5 = 完全无新颖性**）、意见 **≥250 字** |
| **S-Lit** | 文献定位核验员：核实叙事声称的新颖性是否真实 | 最接近先前工作列表（**≥5 篇**）、新颖性核实结论（确认新颖 / 部分重叠 / 已被覆盖）、意见 **≥200 字** |

**按需追加（参照 [roles.md](roles.md) §4）：** idea 数量多、或叙事涉及资源/伦理时，
可加派 **S-Feas**（可行性）与 **S-Repro**（可复现性与伦理）；加派后其评分同样进入
§D4.1 的归一化维度向量。

### D3.1 各子代理的审核指令

**R-CVPR：**
- 该叙事的方法贡献是否实质且可验证？
- 是否有"断言已有类似工作"但未附具体引用的情况？
- 实验设计是否能支撑叙事中的核心主张？
- 是否包含至少一个让 CVPR 参会者感兴趣的新颖之处？

**R-ICML：**
- 是否移除了某个限制性假设？移除是否**彻底**？
- 若涉及跨域迁移，**理论迁移合法性是否被严格论证**？
- 是否提供了新的理论联系，而非简单应用？
- 若声称原创性，是否**命名了最接近的先前工作**并说明精确技术差异？

**R-NeurIPS：**
- 该叙事属于哪种贡献类型（General / Theory / Use-Inspired / Concept & Feasibility / Negative Results）？
- 是否提供了新见解、加深了理解、或揭示了现有方法的重要性质？
- 是否清晰说明了与先前贡献的差异？
- 若属 Concept & Feasibility 类，新颖性是否足够高？

**S-Devil：**
- 若该叙事存在一个无法修复的根本缺陷，最可能是什么？
- 声称的"结构性缺陷"是否只是对已有工作的**重新包装**？
- 最接近的先前工作是哪篇？重叠程度如何？
- 理论迁移合法性证明是否**依赖未经验证的假设**？
- 是否可能在实验中被**简单 baseline 击败**？

**S-Lit：**
- 对每套叙事的核心思路，按 [literature-policy.md](literature-policy.md) 检索
  **≥5 篇**最相关近期论文。
- 该叙事的核心思路是否已被现有工作提出？具体是哪篇？
- 叙事中"首次提出"的声称是否经得起核实？

### D3.2 文献检索规则（S-Lit 强制）

S-Lit 遵守 [literature-policy.md](literature-policy.md) 的**全部**规则：

- **先本地、后 arxiv；但本地命中不是终点**——新颖性核实属 T1/T4 触发场景，
  **必须查 arxiv**，且本地命中不得作为终止条件。
- 429 指数退避 `10s → 20s → 40s → 80s → 160s`，最多 5 次，退避期间不发新请求；
  失败则回退本地结果并**标注检索未达饱和**。
- 结果缓存到 `./docs/refs/cache/`；每条标注 `source="local" | "arxiv"`。
- 新颖性核实必须达到 **L3 穷尽检索**并附**负检索记录**；未达标时结论只能写
  **"据本次检索未见 · 待核实"**，且**不得**认定"确认新颖"。

> ⚠️ 用户原提示词中"本地未命中再调用 arxiv"与本 Skill 的强化规范冲突，
> **以 literature-policy.md 为准**（禁止只停留在本地）。

|---|---|---|---|---|---|---|---|

## D4. 交叉质询与共识形成

每套叙事**至少经历一轮**交叉质询。

**规则：**

1. **每个子代理必须对其余子代理的评分提出至少一条质疑或补充。**
2. **评分差异 ≥2 分的维度**，记录分歧点并尝试**通过证据**协商达成共识。
3. 无法达成共识的，标注 **"存在评审分歧"**。
4. **综合评分取中位数（而非平均值）**，以减少极端评分的影响
   （尤其 S-Devil 可能给出极端低分）。

> 中位数与分歧记录**并存**：分歧单独列出，避免被中位数掩盖。

### D4.1 综合评分必须覆盖全部维度（不得只看创新性）

**强制规则：选定最佳叙事时，必须综合考虑五子代理的**所有**评分维度，不得只比较
"创新性 / 原创性"一项。**

⚠️ **先解决极性：** 各子代理的打分方向并不一致——**S-Devil 的"新颖性反驳"是
5 = 完全无新颖性（越低越好）**，而其他维度都是越高越好。若不先归一化，直接套用
"中位数 ≤ 2 一票否决"会**把最novel的叙事否决掉**，把"完全无新颖性"当成高分。

#### 第 0 步：维度极性归一化（强制，先做）

**所有进入聚合的维度必须先统一为「分数越高越好」。**

| 原始维度 | 原始极性 | 归一化后 |
|---|---|---|
| 方法贡献、可验证性（R-CVPR） | 高 = 好 | 原值 |
| 原创性、理论严谨性（R-ICML） | 高 = 好 | 原值 |
| 洞察深度、重要性（R-NeurIPS） | 高 = 好 | 原值 |
| **新颖性反驳**（S-Devil，**5 = 完全无新颖性**） | **低 = 好** | **新颖性稳健度 = 6 − 反驳分** |
| **致命弱点条数**（S-Devil） | 计数，越少越好 | **不进入中位数向量**；作为上下文记录并在结论中说明 |
| **新颖性核实结论**（S-Lit） | 类别值 | **不进入中位数向量**；按下方"门禁"处理 |

> 除"新颖性反驳"外，本流水线不再有反向维度。若新增维度，**必须**在维度矩阵里
> 显式标注极性并归一化。

#### 第 1 步：门禁（先于中位数，直接否决）

命中任一即**直接否决该套叙事**，不论其他维度多高：

1. **S-Lit 判定"已被覆盖"** → 否决（[venue-standards.md](venue-standards.md) §6 范畴）；
2. **S-Devil 指出的致命弱点含"不可缓解的根本缺陷"** → 否决；
3. **任一门禁项标注"存在评审分歧"且未收敛** → 不得推荐为最佳。

#### 第 2 步：维度中位数与综合评分

1. 把每个子代理的**每个归一化维度**汇成**维度矩阵**；
2. 每个维度取**中位数** → **维度中位数向量**；
3. **综合评分** = 各归一化维度中位数的**等权中位数**；若采用加权，**必须显式写出
   权重与理由**，不得隐式偏重创新性。

#### 第 3 步：一票否决（只针对归一化后的 1—5 维度）

**任一归一化维度中位数 ≤ 2** → 该套叙事不得被推荐为"最佳"。典型情形：

- 创新性 5 但**可验证性 1**（无法验证）→ 不可推荐；
- 创新性 5 但**理论严谨性 1**（迁移证明不成立）→ 不可推荐；
- **新颖性稳健度 ≤ 2**（即 S-Devil 反驳分 ≥ 4，几乎没有新颖性）→ 不可推荐。

> ⚠️ 注意最后一行的方向：**是"反驳分高"被否决，不是"反驳分低"被否决。**

#### 第 4 步：推荐理由

必须**逐维度说明**为什么它胜出（含归一化前后的值），而不是只写"创新性最高"。

**反模式（出现即视为违规）：**

- ❌ 只按 R-ICML 的原创性排序；
- ❌ 忽略 S-Lit 的"已被覆盖"结论；
- ❌ 忽略 S-Devil 的致命弱点；
- ❌ **未做极性归一化就聚合**（会把"最novel"否决、把"无新颖性"当高分）；
- ❌ 用平均值掩盖极端低分（必须用中位数并单列分歧）。

**输出：**

| idea | 套路 | 分歧维度 | 分歧点 | 协商结论 | 是否达成共识 |
|---|---|---|---|---|---|
| I1 | N1 | 新颖性 | … | … | 是/否 |

## D5. 每个 idea 的最佳叙事推荐

### D5.1 推荐格式

对每个 idea 输出：

1. **最佳叙事套路** —— 哪套得分最高，以及为什么。
2. **推荐叙事主线** —— 该套路的**完整五段式**主线。
3. **核心贡献清单** —— 3—4 项，标注贡献类型。
4. **最适合投稿的会议** —— 基于子代理评分判断 CVPR / ICML / NeurIPS，并说明理由。
5. **最大风险与缓解** —— 最可能被攻击的点 + 缓解策略。
6. **与次优叙事的对比** —— 次优叙事在**哪个维度**上弱于最佳，以及是否存在
   **组合两者优势**的可能。

|---|---|---|---|---|---|---|
| I1 | … | … | … | … | … | … |
| I2 | … | … | … | … | … | … |

### D5.3 最终建议

必须明确回答三件事：

1. **哪个 idea 的叙事结构最成熟，最值得优先投入？**
2. **哪个 idea 的叙事存在无法修复的根本缺陷？**
3. **哪个 idea 如果换一种叙事套路，可能获得更高价值？**

**退回规则：** 某 idea 在所有尝试的叙事下综合评分**均 < 3** → 建议**退回 Mode B**
重新生成 idea。

**合并规则：** 两个 idea 的**最佳叙事高度相似** → 考虑**合并或差异化定位**。

## D6. 写作约束（强制）

- 所有引用给出具体出处，格式 `[作者, 会议/年份]`。
- 所有"首次提出"声称**必须先标注"待文献核实"**；保留的前提是**三件事齐备**：
  ① 已完成 **L3 穷尽检索**（§D3.2 / [literature-policy.md](literature-policy.md) §3.1）、
  ② 经 **S-Lit 核实**、③ 附**负检索记录**。缺一只能写"据本次检索未见"。
- 叙事主线必须回答**"为什么之前没人做"**。
- **禁止**使用"显著提升""有效解决""泛化性不足"等无信息量表述
  （见 [narrative-patterns.md](narrative-patterns.md) §3）。
- **包装只允许改变参照系，不允许改变事实**（§D2.4）；每句声称都要能在 Mode C 的
  方案里找到证据，否则删除或标"待补充"。
- 最佳叙事的选定**必须覆盖全部评审维度**（§D4.1），**不得只看创新性**。
- 信息不足处明确标注 **"待补充"**，**不得编造**。
- **仅输出叙事分析与审核报告**，不添加前言、说明或评论。
