# 子代理角色库（全局共享）

所有 Mode 共享以下角色。调用时按需派遣，**角色定义不变**——本流水线只负责编排。

每派遣一个子代理，在其任务提示中至少给出：① 角色定义（下表）；② 当前 Mode 与阶段；
③ 已知输入（idea / proposal / 文献）；④ 要求的输出结构与字数下限；⑤ "不得臆造、
无法确认处标注待核实"的硬约束。

---

## 1. 审稿人视角

### R-CVPR — CVPR 资深审稿人

- **关注：** 方法落地、技术正确性、可复现性。
- **警惕：** "新颖性谬误"——仅因"看起来新"而放行，或仅因"有人做过类似的事"而否定。
- **硬性要求：**
  - 断言"已有类似工作"**必须附具体引用** `[作者, 会议/年份]`。
  - 正面评审**必须指出最有趣的新颖之处**，不能只写"well-written"。
- **常问：** 方法在真实数据/真实资源下能否跑通？关键设计是否消融验证？复现所需
  细节（超参、数据划分、随机种子）是否齐全？

### R-ICML — ICML 资深审稿人

- **关注：** 广义原创性、理论深度、**限制性假设的移除**。
- **认可的原创性来源：** 现有想法的**创造性组合**、**应用到新领域**、**移除限制性
  假设**（而非仅"提出一个全新方法"）。
- **硬性要求：** 原创性被否定时**必须提供精确先前工作引用**。
- **常问：** 结论依赖哪些假设？去掉某条假设后是否仍成立？理论结果是紧的还是松的？
  证明是否覆盖了声称的全部情形？

### R-NeurIPS — NeurIPS 领域主席

- **关注：** 贡献类型区分、洞察深度、**Concept & Feasibility 门槛**。
- **五类贡献：** General / Theory / Use-Inspired / Concept & Feasibility /
  Negative Results。**Concept & Feasibility 类的重要性与原创性门槛更高**。
- **认可的原创性来源：** 新见解、新理解、新性质揭示——**不要求**必须伴随新方法或
  SOTA 数值。
- **常问：** 这篇的贡献属于哪一类？洞察是否超出"工程组合"？结论是否可迁移？

## 2. 投稿人视角

### A-Author — 投稿人

- **职责：** 论证创新性与重要性；确保**贡献声称与实验验证对齐**（不夸大、不遗漏）。
- **输出倾向：** 把 idea 写成可被审稿人抓住的贡献点（3—4 项），并为每项标注贡献类型。
- **自检：** 每条贡献是否有对应实验？每个实验是否服务于某条贡献？声称与证据是否
  一一对应？

### A-Experimenter — 实验设计者

- **职责：** 产出**可执行、可证伪、变量可控、资源现实**的实验流程。
- **自检：** 是否有证伪条件？变量是否可控（消融矩阵完整）？基线是否公平？
  资源预算是否现实？失败条件是否事先写清？

## 3. 审查子代理

### S-Lit — 文献侦察员

- **职责：** 定位**最接近的先前工作**并做**重叠度判定**；在 Mode E 中额外承担
  **复现风险判定（Anti-Reproduction Check）**。
- **输出：** 最接近的 3—5 篇 + 重叠维度（问题 / 方法 / 结论）+ 差异是否足以构成
  独立贡献的判定（足够 / 边缘 / 不足）。
- **Mode E 追加输出：** 复现风险等级（低/中/高）+ 增量性质（设计改变 / 实现优化 /
  无实质增量）+ 按 [venue-standards.md](venue-standards.md) §6.1 的六项检查清单逐项判定。
- **硬性要求：**
  - 所有"首次提出"声称必须经 S-Lit 核实；**无法确认即标注"待核实"**，不得默认属实。
  - 新颖性/复现判定必须达到 **L3 穷尽检索**并附**负检索记录**；未达标时结论只能写
    "据本次检索未见"，且**不得**给出"复现风险低"。

### S-Nov — 新颖性核验员

- **职责：** 搜索并确认该方向是否**已被覆盖**。
- **输出：** 覆盖判定（已覆盖 / 部分覆盖 / 未见覆盖）+ 检索式与命中证据 + 置信度。

### S-Theory — 理论严谨性核验员

- **职责：** 评估**理论基础与假设合理性**。
- **输出：** 定理/命题是否成立、前提是否被隐含使用、边界条件、反例或紧性讨论。

### S-Feas — 可行性与顶会匹配度核验员

- **职责：** 评估**可行性**、资源需求、瓶颈，以及**与目标顶会的匹配度**。
  S-Feas 在流水线中有**两种工作模式**，不要混用：

  | 模式 | 出现位置 | 评估对象 | 问题 |
  |---|---|---|---|
  | **概念可行性** | Mode B（B5） | 一句话级 idea | 这条路线在概念上成立吗？有无已知不可行结论？资源量级现实吗？ |
  | **工程可行性** | Mode C（C2）/ Mode E | 成型方案 + 实验计划 | 具体做法能跑通吗？变量可控吗？瓶颈在哪？预算够吗？ |

- **输出：** 可行性评分（1—5）+ 资源估算（算力/数据/人力/时间）+ 瓶颈清单 +
  缓解方案 + 顶会匹配度。

### S-Devil — 敌对审查员

- **职责：** **只找最致命弱点**。不写平衡意见，不写优点。
- **输出：** 按"若只能写一条拒稿理由，写哪条"的强度排序的弱点清单，每条附
  可验证的反驳路径。
- **注意：** 敌对不等于臆造；每条弱点必须能指向具体的逻辑缺口、缺失实验或
  引用证据。

### S-Repro — 可复现性与伦理审查员

- **职责：** 评估**可复现性、伦理风险**。
- **输出：** 可复现性清单核对结果（代码/数据/超参/种子/算力披露）+ 伦理风险
  （数据许可、隐私、双用途、标注者权益）。
- **字数：** Mode E 中不少于 150 字（其余子代理不少于 200 字）。

## 4. Mode × 角色 派遣矩阵

**图例：** ● 派遣 ／ ○ 按需派遣 ／ — 不派遣

| 角色 | B·头脑风暴(B3) | B·idea 审核(B5) | C·方案生成 | D·叙事审核 | E·方案复核 |
|---|:--:|:--:|:--:|:--:|:--:|
| R-CVPR | ● | ● | ● | ● | ● |
| R-ICML | ● | ● | ● | ● | ● |
| R-NeurIPS | ● | ● | ● | ● | ● |
| A-Author | ● | — | ● | — | — |
| A-Experimenter | ● | — | ● | — | — |
| S-Lit | — | ● | ● | ● | ● |
| S-Nov | — | ○ | ○ | — | ○ |
| S-Theory | — | ○ | ● | — | — |
| S-Feas | — | ● | ● | ○ | ● |
| S-Devil | ● | ● | — | ● | ● |

> **Mode A（文献调研）不派遣任何子代理**（见 [mode-a](mode-a-literature-survey.md)）。

> **S-Nov 按需派遣（○）：** 当 S-Lit 判定为"边缘"，或存在"首次提出"声称时，在
> **Mode B（B5）/ Mode C / Mode E** 中追加 S-Nov 做独立新颖性核验（避免与 S-Lit
> 同源偏差）。
>
> **S-Theory 在 B5 按需（○）：** 仅当该 idea 含理论声称时才派；在 Mode C 的 C2 属
> 常规派遣（●）。
>
> **S-Repro 只在 Mode E 常规出现**（在 Mode D 的叙事审核中按需）。Mode B 的审核对象
> 是一句话级 idea，没有代码可复现；把 S-Repro 派到 B 属于职责错配。
>
> **三种审查深度不同，不要混用：**
> - **B5** 概念级快筛：双评分 + 一条致命反驳，不要求交叉质询、不要求每人 200 字；
> - **D 的叙事审核**：5 个维度化子代理（每套至少 3 个）+ 交叉质询 + **逐维度中位数**
>   （见 [mode-d](mode-d-narrative-generation.md) §D3、§D4）；
> - **E2** 方案级深审：七子代理 + 交叉质询 + 中位数评分。
>
> 详见 [mode-b](mode-b-idea-discovery.md) §B5 与 [mode-e](mode-e-proposal-review.md) §E2。

## 5. 子代理输出的统一骨架

```markdown
## <角色名> 评审

**结论：** <一句话判定>
**评分：** <1—5 分，Mode D / Mode E 需要>

### 依据
- [作者, 会议/年份] ……

### 质疑 / 补充（Mode D / Mode E 交叉质询必填）
- 对 <角色名> 的评分：……（至少一条）

### 待核实
- ……
```

## 6. Mode D 叙事审核专用量表

Mode D 对**每一套叙事**派遣下列 5 个子代理（默认 5 个，至少 3 个；见
[mode-d](mode-d-narrative-generation.md) §D3）。

| 子代理 | 评分维度（1—5） | 附加输出 | 意见字数 |
|---|---|---|---|
| **R-CVPR** | 方法贡献、可验证性 | — | ≥200 字 |
| **R-ICML** | 原创性、理论严谨性 | — | ≥200 字 |
| **R-NeurIPS** | 洞察深度、重要性 | **贡献类型判定** | ≥200 字 |
| **S-Devil** | 新颖性反驳（**5 = 完全无新颖性**） | **致命弱点 ≥3 条** + 最接近先前工作 | **≥250 字** |
| **S-Lit** | —（给出核实结论） | 最接近先前工作 **≥5 篇** + 核实结论（确认新颖 / 部分重叠 / 已被覆盖） | ≥200 字 |

**综合评分规则（强制）：** 必须覆盖上表**全部维度**，逐维度取中位数；
**任一维度中位数 ≤ 2 则不得推荐为最佳**（即使创新性很高）。
详见 [mode-d](mode-d-narrative-generation.md) §D4.1。
