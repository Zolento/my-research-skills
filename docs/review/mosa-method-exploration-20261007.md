## 行为缺陷与修正

1. continue-research 把“接着做”映射为只建议再确认。改为区分咨询与执行授权。
2. 高优先级未清零阻塞所有低级动作。改为依赖作用域阻塞，保留完整性先修复。
3. 诊断实验源源不断压过方法探索。要求诊断改变具体决定，并在候选耗尽时重新生成。
4. 机制证明被误作方法生成前提。允许假设驱动干预，保留主张证据标准。
5. 旧 scheduler 理由继续支撑选择。要求核对版本、产物和当前 live 候选。
6. 实验 id 与 stage 重名。明确两者独立，并用十节点 state 的实际 CLI 验证。

修改复用现有阶段、对象、字段和 EIG 口径，没有新评分或新调度程序。

## MoSA 下一步应如何执行

先核验并登记已运行实验及结果，不能仅凭预注册推定完成。
对尚未运行的候选保留 planned，不补造预注册时间或结果。
核对训练预算、源权重、学习率、数据划分及比较协议。
在当前证据下选择一个可改变方法决定的干预，并说明正反结果分别如何改变下一步。
可执行的窗口对照能检验一种方法选择，无须等待五因素归因全部完成。
GT-FM 参照差距只能作为当前比较量，不能未经证明作为适应性能的绝对上界。
探索筛选应使用获准的验证协议，不能因仅在 train 微调就认为反复 test 选型无泄漏。

## 验证边界

静态发布检查不证明持续研究会产生有效方法。
行为情境复核只检验规则能否指导下一步，不代替真实项目长期 dogfood。
后续 dogfood 应核对：结果是否改变方法决定、失败后是否形成新候选、未授权动作是否停止。
不以文档数、实验数或自评 EIG 作为成功标准。

## 验证结果

- 十节点 state 的 CLI 校验通过，确认没有六实验上限。
- MoSA 当前 state 校验通过，但与磁盘实验登记范围不一致。
- 独立行为复核在候选耗尽情境选择 reseed，在咨询情境停止。
- 复核发现完整性故障作用域歧义，已明确先隔离污染再继续确认独立的工作。
- 复核发现 closure 与预算退出冲突，已在执行入口明确中断不代表阶段完成，保留有效状态且不得伪造闭环。
- Team 首次选择仍有交互成本，本轮未重构派遣机制。已有授权沿用。
